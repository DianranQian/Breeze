feat: Bevy Studio 首个可用闭环（项目/场景/实体/属性/保存/重开）

以 Godot Editor 为工作流参考、建立在 Bevy 0.20 之上的可视化编辑器。
本次提交完成里程碑 A 与 B 的核心闭环，全部经实际编译与测试验证。

架构（四层，依赖严格单向）
- scene_doc：场景文档数据模型，不依赖 Bevy，可无 GPU 测试
- editor_core：命令、撤销栈、项目、编辑器状态，不依赖 Bevy
- editor_ui：egui/egui_dock 界面层，只读编辑器状态、只产出意图
- editor_app：Bevy 应用装配、组件注册表、场景⇄ECS 单向桥接

关键设计决策
- 场景文档用「扁平实体表 + 父指针」而非嵌套树：拖放改层级、重命名、
  撤销都变成线性操作；代价是层级隐式，靠 validate 兜住
- 撤销用「全量快照 + 命令」而非反向操作：正确性只依赖文档 Clone 与
  命令 apply（两者都有独立测试），代价用字节预算约束
- 撤销条目记录首次生成的实体标识，重做时填回命令，保证重做幂等
  （否则「撤销再重做」会换掉 UUID，静默让选择集与引用失效）
- 保存采用「写临时 → 挪备份 → 就位」三段式，读取按
  原文件→备份→临时 回退，覆盖崩溃在任一步的现场
- 运行时住在独立的 World 里：文档→世界单向构建，世界永不回写文档，
  数据隔离靠物理隔离而非约定
- Inspector 由组件注册表驱动，不认识任何具体组件；新增组件不改 UI 代码

验证情况
- 156 个自动化测试全部通过（scene_doc 36 / editor_core 41 /
  editor_ui 52 / editor_app 27）
- 编辑器可实际启动：窗口 1600x950、Vulkan 后端、进程稳定不崩溃
- 依赖版本经 crates.io 实际核实：bevy 0.20.0 与 bevy_egui 0.43.1、
  egui_dock 0.21.1 收敛在同一个 egui 0.36.2，无版本冲突

- 游戏运行逻辑（运行时世界目前只做构建与统计）
- 编辑器插件系统、资源导入元数据与 UUID 持久化
