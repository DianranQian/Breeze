# 微风 (Breeze)

> 正式名称：**微风**；英文品牌名：**Breeze**。
> 代码中的 crate、目录与配置键沿用历史命名（如 `editor_app`、`BevyStudio` 配置目录），不影响产品名称。

> 一个以 **Godot Editor** 为工作流参考、建立在 **Bevy 0.20** 之上的可视化游戏编辑器。
> 目标是让开发者用可视化界面完成绝大部分常见游戏开发操作，同时保留 Rust 与 Bevy 的
> ECS / System / Plugin 全部能力。

**当前状态：编辑—保存—运行—导出的完整闭环已经跑通，并有真实窗口的自动化验收。**
12 个 workspace 成员、18 个可停靠面板、21 个内置组件；场景可以带三维网格、灯光、
物理、界面元素、glTF 动画与粒子，导出成双击即玩的包，也能把**项目自己的 Rust 代码**
一起编进包里。
未实现的功能在菜单里显示为禁用，不做占位假象；做不到的事全部写在
「它现在不能做什么」里。

## 它现在能做什么

### 项目

- 在空目录中**创建项目**，自动生成 `assets/`、`scenes/`、`src/` 与项目清单 `project.ron`
- **打开 / 关闭**已有项目；打开时自动载入启动场景或场景目录里的第一个场景
- 非空目录会被**拒绝**，避免覆盖用户已有文件
- **项目设置对话框**：名称、说明、启动场景、运行程序与参数、构建段、设计分辨率、
  打包配置，草稿制编辑（点「保存」才整体写回）；原生 Cargo 工程只读并明示原因

### 场景编辑

- **场景树**：新建、删除（连带整棵子树）、重命名、复制、上移 / 下移、移到顶层、
  隐藏、锁定、展开折叠、按名称搜索（保留匹配项的祖先）、右键菜单、
  **拖拽改变父子层级**（拖到空白处回顶层；防环、跨层撤销一步可回）
- **属性检查器**：由组件注册表驱动，自动为每个字段生成合适的控件。
  13 种属性种类：布尔、整数、浮点（带范围与步进）、文本、二维、三维、
  角度三维、四维、颜色、枚举下拉、资源引用、列表、嵌套结构。
  顶部常驻**环境设置**（环境光颜色 / 强度 / 背景颜色），下面是变换区与逐个组件的字段表；
  四张表共用同一份网格间距，列线对齐
- **变换编辑**：位置 / 旋转 / 缩放三行，每行 X Y Z 在同一行、每个数值框左侧有轴色字母。
  文档里存四元数（唯一规范表示），Inspector 以角度编辑，两端有往返一致性测试。
  三行各带合法区间，缩放拖不进退化值（按原符号弹回，负缩放镜像仍可用）
- **2D 视口**：网格、坐标轴、实体包围框、选中高亮、框选、点选、
  滚轮以指针为锚点缩放、中键 / 空格拖动平移、F 聚焦、Delete 删除、
  视图内移动 / 旋转 / 缩放操纵器
- **3D 视口**：透视轨道相机（缩放 0.01–100 000，近远裁剪面按距离跟随）、
  **射线-AABB 拾取**（点盒体表面即命中，不再只认实体轴心）、选中实体画世界包围盒线框、
  三工具操纵器（轴长屏幕恒定 88px，射线/平面求交）、悬浮栏「快速创建」图元与光源
- **添加 / 移除组件**，每个字段行有「恢复默认」，预制件实例上会标出哪些字段是覆盖

### 二维瓦片与地形

- **`TileTerrain`**：场景里存字符网格 + 图集目录，加载时按
  **双网格自动瓦片**规则（`POS` / `CORNER_BIT` / `DRAW_SURFACES` / 整格变体）
  现场合成地面纹理。地面不是一张预烘焙 PNG，改一格地形、换一套图集、
  调变体概率都只需改参数
- **瓦片地图面板**：调色板选笔刷、笔刷半径、在画布上拖拽刷格、瓦片集编辑与图集预览，
  数据落 `.tilemap.ron` / `.tileset.ron`（不再是手编文本）
- 示例与根因分析见 [`docs/示例项目_程序化渲染根因.md`](docs/示例项目_程序化渲染根因.md)

### 三维内容与预览渲染

视口不是"线框示意图"：预览走 `RenderTarget` 纹理，画的是真实几何与材质。

- **基础图元**：立方体、平面、球体、圆柱体，工具栏一键创建并自动选中（整组一步撤销）
- **`Primitive3d`**：受光 `StandardMaterial` + UV 重复 + 可选双面，接收方向光与阴影
- **灯光**：`Camera3d`、方向光、点光、聚光灯（角度以度数存储，投影时转弧度并夹在合法范围），
  投射阴影开关取文档字段；环境光与背景色由场景全局 `环境` 承载
- **材质资产** `.material.ron`：基础色 / 法线 / 金属粗糙度 / 遮蔽四个贴图槽，
  投影进 `StandardMaterial` 对应通道；材质编辑器复用 Inspector 的字段控件，
  选取贴图只改草稿、保存才落盘并按代次推进缓存
- **游戏内 UI / HUD**：`UiImage` 等界面元素（锚点 / 偏移 / 宽高 / 贴图 / 着色），
  几何与内容优先级解释抽成一份共享投影，编辑器预览与运行时共用
- **glTF 动画**：`动画播放器` 组件（片段名 / 速度 / 循环，速度允许负数倒放），
  预览按模型路径解析 `named_animations`，运行时落成真实的 `AnimationGraph` + `AnimationPlayer`
- **粒子**：`粒子发射器` 组件（速率 / 生命周期 / 初速 / 颜色 / 大小），
  确定性 CPU 步进模拟器同时服务预览与运行时（512 粒硬上限）

### 物理

- **2D**：`rapier2d`；**3D**：`rapier3d` 0.36 后端，`碰撞体3d`（Box / Sphere / Capsule / Cylinder）
  与 `刚体3d`（静态 / 动态 / 运动学，质量、摩擦、弹性、重力缩放、触发器）
- 物理只在「运行」后推进，预览与文档完全隔离，停止运行整体丢弃
- 创建立方体 / 球体 / 圆柱体时自动挂匹配的刚体与碰撞体，整组仍只占一步撤销

### 资源与预制件

- **资源浏览器**：目录树与缩略图网格两种视图、按名称 / 大小 / 类型排序、搜索、
  类别识别（图片 / 音频 / 字体 / 模型 / 材质 / 场景 / 着色器）
- 双击图片资源即创建 Sprite 实体，并**读取真实像素尺寸**填入包围盒
- **资源重命名 / 删除**：面板内输入框 + 二次确认对话框；改名跨文件同步改写引用，
  仍被引用时拒绝删除，事务失败回滚
- **资源稳定标识（UID）**：打开场景时为缺标识的资源补全 UID 并落盘
  `.breeze/asset_uids.ron`，引用同时保存路径与 UID，移动文件后按 UID 重连
  （限制：原生 Cargo 工程的资源不落盘）
- **资源选择器浮层**：Inspector 与材质编辑器里的资源字段可直接打开按类别分页的选择器
- **预制件**：实例化、字段覆盖、嵌套、同步、回收；**保存前一致性审计**检查孤儿实例、
  失效覆盖地址、已删与脱钩节点、跨文件缺失资源、模板版本倒退，
  **只告警不阻断保存**

### 代码工作区

- **项目文件树面板**：扫描 `src/` 与根目录核心文件，忽略 `target/` 等构建目录，
  支持折叠展开与刷新；双击文件在代码面板打开
- **多标签代码编辑器**：按路径聚焦（重复打开不长同名标签），每个标签各自持有
  查找词 / 命中 / 滚动偏移；脏标签标题追加 `*`，关闭或切换前弹保存/放弃/取消确认
- 文本读取移到后台线程并按代次认领，主线程不再同步读盘；行号栏随滚动同步，
  词法支持跨行块注释、原始字符串与属性段
- `Ctrl+S` 按焦点分流：代码框有焦点存脚本，否则存场景

### 持久化

- 场景保存为 **RON**（美化输出，字段一行一个，便于 Git diff 与代码评审），
  当前 `格式版本: 2`
- **原子保存**：写临时文件 → 原文件挪为备份 → 临时文件就位；
  失败时回滚，**原文件一字不改**
- **损坏恢复**：读取时按 `原文件 → .bak → .tmp` 依次尝试并完整解析，
  覆盖"崩溃在任意一步"的现场；异常退出后下次启动弹「恢复自动保存」浮层
- **未保存修改检测**：跟随撤销栈的保存点，撤销回保存点会重新变"干净"
- **格式版本**：读到更高版本直接拒绝加载并说明原因，不会静默丢数据
- **未知组件原样保留**：用新版编辑器打开旧场景再保存不丢数据

### 编辑操作

- **撤销 / 重做**：基于文档快照 + 命令重放，撤销删除能精确恢复整棵子树与次序；
  64 MiB 字节预算，超预算从最旧一端丢弃
- **重做幂等**：撤销条目记住首次生成的实体 UUID，重做时填回命令，
  保证"撤销再重做"后实体标识不变（否则选择集与引用会静默失效）
- 批量操作（多选拖动、批量改属性）只占**一步**撤销
- 拖动以按下位置为基准计算，不会因逐帧累加而漂移
- 视口内的拖动、对齐分布与操纵器都按**世界空间**换算，父级带旋转 / 缩放时不再算歪

### 运行与调试

- **运行 / 暂停 / 继续 / 停止**当前场景，运行时诊断面板显示实体数、
  组件类型数、界面节点数、帧率、帧耗时
- **两种"运行"边界清晰**：编辑器内原型（PIE，同进程隔离世界）与
  「运行项目」（子进程启动真实可执行文件，构建失败或启动 panic 不会拖垮编辑器）
- **独立游戏运行模式**：同一个 exe 用 `--game` 或同级的 `game_manifest.ron`
  切换到游戏身份，不装配任何编辑器界面，直接加载主场景并启动运行时
  （物理 / 动画 / 粒子 / 界面）；`--windowed`、`--monitor <n>`、`--bench <秒>` 见「快速开始」
- 运行时世界与编辑器文档**物理隔离**：运行时的任何修改都不会写回文档
- **控制台**：按级别过滤与搜索，自动滚到底部，错误在标签页上显示角标
- **历史面板**、**性能面板**、**时间轴面板**
- **远程 ECS 检查器**（运行时 ECS 面板）：通过独立的版本化 TCP loopback
  协议连接**用户自己的原生 Bevy 游戏**，读取真实 Entity / Component /
  Transform / Resource；支持分页、搜索、组件过滤、复制、刷新，并把真实
  运行时上下文交给 AI Agent。断开后数据标记为过期，不冒充实时。
  属性编辑只允许游戏端显式注册的字段（内置 `Transform` 平移/旋转/缩放），
  带预期原值冲突检测、幂等重试和真实前后值；超时/断线只显示“结果未知”。
  世界快照与差异只在同一运行实例内比较，截断会明确标记。
  接入方式与安全边界见 [`docs/运行时调试协议.md`](docs/运行时调试协议.md)
- **存档浏览器与回档**：运行时存档可浏览、可恢复到编辑器会话

### 界面基础设施

- **18 个可停靠面板**由一张注册表派生（标题、菜单项、标签组、工作区预设全部由它算出来，
  少登记一行是编译错误而不是运行时 panic）；可浮动、可分割、可关闭
- **多模式 + 多工作区**：2D / 3D / 代码 / AI Agent 四种模式各有独立布局，
  内置通用 / 场景 / 资源 / 调试四套预设，布局改动会持久化
- **主题库**（深色 / 浅色，语义色槽，可切换并随配置保存）、**中文字体内置**（缺了它汉字全是 `□`）、
  面板图标 PNG 由 `tools/icon_bake` 从 Tabler Icons 烘焙
- **中英双语**：全部界面文案走 `messages.tsv` + 编译期生成的词表，
  守卫测试拦住"注册表里写中文当词条键"这类绕过
- **AI Agent 一级模式**：对话 / 会话 / 审查三个面板，把真实工程上下文与运行时状态
  交给外部 Agent 进程，改动以 diff 形式逐条审查

### 自动化验收

- **真实窗口**的验收用例（`tools/*.ps1` + `crates/gui_probe`）：启动应用、
  按当帧测得的矩形注入真实鼠标 / 键盘事件、再核对结构化证据。
  命名用例的分布是主链路 15 条、变换与撤销 26 条、预制件 7 条，
  另有 AI Agent、PIE 输入、资源预览三条脚本各成一类
- 每条脚本都用 `-Exe` 指定应用、`-Filter` 挑用例、`-OutRoot` 指定证据落点
  （默认分别是 `.verify/runs/…` 与 `target/verify/prefab`，两者都已 gitignore）
- 断言落在**实体变换数值、撤销步数、文档脏状态、区域矩形与相对位置、状态栏文案**上，
  并有统计像素阈值（全图均亮度判主题、每块区域的色彩数 ≥3 与对比像素数）拦住
  "整屏黑掉""文字没渲染出来"这类缺陷
- 同帧落 PNG + 布局 JSON，人工复核时看的是可复核的现场，不是结论

## 它现在不能做什么

这一节是刻意写在前面的。以下是**当前确实做不到**的事（能落成菜单项的，菜单里显示为禁用）：

| 未实现 / 边界 | 说明 |
| --- | --- |
| **编辑器插件系统** | 组件注册表已具备扩展所需的接口形态，但没有第三方插件加载、版本与安全边界设计。全仓没有 `libloading` / dylib 代码，唯一的"插件"是 Bevy 内部的 `impl Plugin` |
| **历史面板列出完整撤销栈** | 面板只取"下一步撤销 / 下一步重做"各一条名称，撤销栈没有对外暴露完整条目列表 |
| **编辑器 exe 的游戏身份不执行用户代码** | `bevy-studio.exe --game` 复用编辑器的投影与运行时世界，能看到场景 / 物理 / 动画 / 粒子，但**不加载项目自己的 System**。要让 System 进包，把项目做成只依赖 `breeze_runtime` 的 Cargo 工程（见「方式零」） |
| **`breeze_runtime` 仍是薄壳** | 它复用 `editor_app` 的装配路径，所以用户项目会把整张依赖图一起编进来。实测（Intel Ultra 7 265K，干净 `target` 首次 release 构建）：构建 **171 秒**、exe **104.4 MiB**、导出包 **161.9 MB**（含 57.5 MB pdb）。这不是"最小游戏运行时" |
| **瓦片地图的撤销不入场景撤销栈** | 面板有自己的快照 + 重做栈，刷格子不会和场景编辑共享一条撤销历史，`Ctrl+Z` 的归属按当前面板区分 |
| **资源 UID 有落盘范围限制** | 微风工程写 `.breeze/asset_uids.ron`；**原生 Cargo 工程**的资源标识不落盘，跨机器不会带过去 |
| **没有逐像素 golden image 比对** | 自动化验收断言的是结构化证据（区域矩形、数值、文案）+ 统计像素阈值，仓库里没有参考图基线，所以"某个像素颜色变了"不会被抓到 |
| **粒子是简化的 CPU 模拟** | 确定性 LCG 伪随机、固定重力 -9.8、寿命 ±20% 抖动、512 粒硬上限，没有 GPU 粒子、碰撞、拖尾与纹理 atlas |
| **动画只有单片段播放** | `动画播放器` 播一个命名片段，带速度与循环；没有动画状态机、混合树、图层与事件轨道 |
| **没有寻路 / 导航网格** | 未开始 |
| **没有多人 / 网络同步** | 未开始 |
| **非 Windows 平台未验证** | 全部实测在 Windows 11 + NVIDIA + Vulkan 上完成。macOS / Linux / Web 构建**未验证**，不是"支持" |

以下几条**曾经**在这一节里，现在已经不是限制，写在这里防止再被当成 TODO：
3D 视口操纵器、瓦片编辑 UI、预览渲染真实网格与灯光、用户 Rust 代码进包、
资源 UID 持久化、项目设置对话框、资源改名 / 删除对话框、3D 物理与光照与动画、
真实窗口的自动化验收。

## 快速开始

### 环境要求

- **Rust 1.90+**（开发环境实测 1.99.0 stable）
- Windows 上需要 MSVC 工具链（`cargo` 通常能自动发现已安装的 Visual Studio）
- 显卡需支持 Vulkan / DX12（实测 NVIDIA RTX 4060 Ti + Vulkan 正常）

### 构建与运行

```powershell
# 在仓库根目录
cargo run -p editor_app --bin bevy-studio
```

首次编译需要构建整个 Bevy，视机器性能约 3～10 分钟。之后的增量编译在秒级。

> **构建产物**落在仓库内的 `target/`。本仓库**没有** `.cargo/config.toml`，
> 也没有 `target-dir` 重定向（上级目录那份在 2026-10-22 已移除，只留
> `incremental = false`），所以 `cargo clean` 只清本工程。
> 需要把产物放到别处时显式设置：`CARGO_TARGET_DIR=D:\cache\cargo cargo build`。
> 注意：部分验收脚本仍把 `_build\target\debug\bevy-studio.exe` 当兜底路径，
> 跑验收时用 `-Exe` 指到实际产物。

### 打包与独立运行（绿色版）

`build_release.ps1` 做两件事：构建 release 编辑器，再把可执行文件与资源
收进 `dist/`。加 `-ExportGame` 时改做第三件事：把 exe + 一个工程里可达的
场景/资源 + 游戏清单收进 `Game_Build/`，那是一个**直接进游戏、不开编辑器**
的可玩包。导出本身不写在脚本里 —— 脚本只调用刚构建出的 exe 的
`--export-game`，与编辑器界面的「打包」共用 `editor_core::package`
里同一份计划、复制与清单逻辑（脚本不再解析 `project.ron`）。
目标机器不需要安装 Rust，把产物目录整个复制过去即可运行。

```powershell
# 仓库根目录
.\build_release.ps1                            # 构建 + 收集 → dist/
.\build_release.ps1 -SkipBuild                 # 复用已有 release 产物
.\build_release.ps1 -AssetsDir D:\游戏资源     # 指定要随包分发的资源目录
.\build_release.ps1 -WithExamples              # 额外把 examples/ 拷进 dist/
.\build_release.ps1 -ExportGame                # 导出可玩包 → Game_Build/
.\build_release.ps1 -ExportGame -ExportWindowed        # 包内清单改为窗口模式启动
.\build_release.ps1 -ExportGame -SkipBuild `
    -ProjectDir examples\3d_demo `
    -GameOutDir D:\发布\我的游戏                # 指定工程与输出目录
```

产物布局与资源查找规则一一对应：

```text
dist/
├── bevy-studio.exe
├── bevy-studio.pdb        # 存在时一并复制，崩溃报告才能定位符号
├── assets/                # 资源目录存在时才会出现
├── examples/              # 仅 -WithExamples
└── build-info.txt         # 文件清单与大小
```

脚本从 `cargo build --message-format=json` 的产物消息里读可执行文件路径，
因此本仓库把 `target-dir` 重定向到别处时也不会找错目录。

`-ExportGame` 的产物布局（与 `editor_app::standalone` 的身份判定一一对应：
exe 同级有 `game_manifest.ron` 就以游戏身份启动）：

```text
Game_Build/
├── bevy-studio.exe
├── bevy-studio.pdb        # 存在时一并复制，崩溃报告才能定位符号
├── game_manifest.ron      # 主场景 / 设计分辨率 / 是否全屏
├── project.ron            # 工程清单（独立模式仍按它装载项目）
├── scenes/                # 全部场景
├── assets/                # 场景引用的资源；带用户代码的工程是全量 assets（减去排除项）
└── build-info.txt
```

资源收集分两种模式（`editor_core::package::生成打包计划`）：

| 工程 | 带什么资源 |
| --- | --- |
| **纯微风**（`project.ron` 没声明 `运行` / `构建`） | 场景闭包：启动场景（或全部场景）+ 各场景 `资源表` 登记的资源。源码与未被引用的资源不进包 |
| **带用户代码**（声明了 `运行` 或 `构建`） | 先算同一份场景闭包，再**全量复制 `assets/`**，按 `打包.排除资源` 的前缀剔除 |

分叉的理由是**资源怎么被发现**：纯微风工程的资源只可能由场景引用，闭包就是全集；
带用户代码的工程会用 `asset_server.load("…")`，路径能来自 `format!`、配置文件或
`load_folder`，静态分析必然漏 —— 而漏掉的资源在玩家机器上表现为贴图缺失。
排除项盖住了场景正在引用的资源时，打包**直接失败并点名到具体路径**，
不替用户选一边。全量扫描不跟随符号链接、深度上限 20 层。
`排除资源` 这一项目前只能在 `project.ron` 里手写，项目设置对话框还没给输入框。

`-ProjectDir` 省略时，脚本读编辑器配置里的**当前打开的工程**
（`%APPDATA%\BevyStudio\config.ron`，可用 `BEVY_STUDIO_CONFIG_DIR` 覆盖），
所以"在编辑器里调好、回终端敲一条命令"就是完整流程。主场景、名称与设计
分辨率由 `项目描述` 从 `project.ron` **结构化读取**（不再是脚本里的正则）；
没有启动场景时按场景目录第一个兜底，一个场景都没有直接报错 ——
生成一个跑不起来的包比报错更难排查。

导出也可以直接调用 exe（脚本内部就是这么做的）：

```powershell
bevy-studio.exe --export-game <工程目录> <输出目录> [--windowed]
```

输出目录会被**先清空**；校验在 Rust 侧完成：输出目录不能是工程目录或它的
上级，可执行文件也不能位于输出目录内（否则清空时先把自己删掉）。

**资源根解析**（`editor_core::asset_root`，编辑器启动时执行一次）：

| 优先级 | 候选 |
| --- | --- |
| 1 | `BEVY_ASSET_ROOT`（环境变量；可指向资源目录本身或其父目录） |
| 2 | `<当前工作目录>/assets` |
| 3 | `<exe 所在目录>/assets` |
| 4 | 以上都不存在 → 仍然选 `<exe 所在目录>/assets`（打包目录的固定布局） |

所以从快捷方式、任务计划器或任意工作目录启动时，资源依旧从 exe 旁边读取；
开发期行为不变（当前目录优先）。需要强制指定时设置 `BEVY_ASSET_ROOT`。

### 如何导出一个可玩的游戏

**方式零：Rust 游戏项目（游戏逻辑随包发布）**

当游戏有自己的 Rust 代码时，把项目本身做成一个 Cargo 工程，只依赖
`breeze_runtime`：

```text
my_game/
├─ Cargo.toml          # 只写 breeze_runtime
├─ src/main.rs         # breeze_runtime::启动带扩展(|应用| { ... })
├─ project.ron         # 运行 + 构建 两段都指向这个 crate
└─ scenes/main.scene.ron
```

```toml
[dependencies]
breeze_runtime = { path = "…/crates/breeze_runtime" }
```

```rust
use breeze_runtime::prelude::*;

fn main() {
    breeze_runtime::启动带扩展(|应用| {
        应用.add_systems(Update, 我的系统);
    });
}
```

> **项目里不要自己声明 `bevy` 依赖。** 运行时用的是 `breeze_runtime`
> 重导出的那一份 Bevy；项目再写一行 `bevy` 会拉进第二份互不认识的类型，
> 报错长得像"组件不满足 trait 约束"。一律从 `breeze_runtime::prelude::*` 取类型。

导出时（编辑器「打包」，或 `bevy-studio.exe --export-game <工程> <输出>`）
读取 `project.ron` 的 `构建` 段执行 `cargo build --release`，把**项目自己
编译出的 exe** 放进包 —— 这个 exe 链接了 `breeze_runtime`，你的 System 会执行。

- **导出机**需要 Rust 工具链（`cargo` 在 PATH 上）；**玩家机器**不需要；
- 首次导出要把 Bevy 全套依赖编译一遍，耗时以十分钟计；之后增量导出只重编
  项目自己，通常几秒；
- 编译产物在项目的 `target/release/` 下，**可以整个删掉**，下次导出会重建；
  导出的游戏包不依赖这个目录；
- 清单里的运行目标指向非 Cargo 程序、且没有构建配置时，导出会回退到编辑器
  exe 并打印警告（包内不含该项目的游戏逻辑）。

完整可运行示例见 [`examples/runtime_demo/`](examples/runtime_demo/)：
只依赖 `breeze_runtime`，挂一个自转立方体的 System，`project.ron` 已配好
`运行` 与 `构建`。

**方式一：一键导出可玩包（推荐给玩家/测试者）**

```powershell
.\build_release.ps1 -ExportGame          # → Game_Build/，双击 exe 直接进游戏
```

包里是同一个 `bevy-studio.exe`，但启动时**不装配任何编辑器界面**：
入口先判身份（`--game` 参数，或 exe 同级/当前目录里有 `game_manifest.ron`），
命中就以游戏身份加载清单里的主场景，直接渲染到窗口并启动运行时
（物理步进、glTF 动画、粒子）。判定顺序与参数见
[`crates/editor_app/src/standalone.rs`](crates/editor_app/src/standalone.rs)。

| 启动方式 | 结果 |
| --- | --- |
| 双击 `Game_Build/bevy-studio.exe` | 按 `game_manifest.ron` 全屏进游戏 |
| `bevy-studio.exe --windowed` | 同样进游戏，但不独占显示器 |
| `bevy-studio.exe --monitor 2` | 指定显示器全屏（序号从 1 开始，对应系统显示设置里的顺序） |
| `bevy-studio.exe --game D:\我的工程` | 不带清单，直接以该工程的启动场景运行 |
| `bevy-studio.exe --bench 10` | 关闭垂直同步，预热 2 秒后采样 10 秒，打印帧耗时统计后退出 |
| 以上都不满足 | 编辑器照旧启动 |

`--bench` 用来拿可复现的帧耗时数字：不做预热会把首帧的着色器编译、
贴图解码算进平均值；不关垂直同步则指标会被显示器刷新率钉住。
输出一行 `基准：… 帧 / 平均 / 中位 / p95（已关垂直同步）`。
`--windowed` 优先于 `--monitor`，`--monitor` 隐含全屏。

`Esc` 退出游戏窗口。3D 场景需要文档里有一台 `Camera3d` 节点（编辑器
新建场景时会自动补），否则退回二维正交取景并在日志里告警。

> **边界**：独立模式复用编辑器的**投影 + 运行时世界**，因此能看到场景、
> 物理、动画与粒子，但**不执行项目自己的 System / Plugin**——如果包里那份
> exe 就是编辑器程序，游戏逻辑仍走「运行项目」的子进程路径（见下方方式三）。
> 要让 System 进包，把项目做成 Cargo 工程（方式零）。

**方式二：编辑器内打包（项目交付）**

1. 打开项目，进入构建面板，把配置切到 `Release`，点「构建」并等待成功；
2. 在同一面板下方点「打包」；
3. 产物在项目根的 `dist/`（可在项目设置里改输出目录）。

包内包含：项目清单 `project.ron`、场景与其登记的资源、构建出的可执行文件、
`game_manifest.ron`、`build-info.txt` 清单。默认只带**启动场景**，勾上「包含全部场景」
才把所有场景作为闭包起点（`--export-game` 走的是后者，见上方方式一）。
打包会**先清空输出目录**，
因此输出目录必须是项目内的相对路径（绝对路径与 `..` 会被拒绝）。
项目一个场景都没有时**不写** `game_manifest.ron`：没有入口的目录不是可玩的包。

> **边界**：「打包」要求先有构建成功且真实存在的可执行文件。纯微风项目
> 如果没有声明运行目标，就没有可执行文件，打包按钮会保持不可用 ——
> 这种情况下用方式一。

**方式三：绿色版编辑器（本仓库自身）**

1. 运行 `.\build_release.ps1`（需要分发示例项目时加 `-WithExamples`）；
2. 把 `dist/` 整个复制到目标机器，双击 `bevy-studio.exe`；
3. 菜单 **项目 → 打开项目…** 选择项目目录，按 `F5` 运行当前场景。

> 这一条交付的是**编辑器**：菜单、面板、撤销栈一个不少，适合让人接着改。
> 运行时世界负责场景构建、统计、物理、动画与粒子步进，但还没有加载项目
> 自己的 System / Plugin（见上方「它现在不能做什么」）。

### 跑测试

```powershell
cargo test --workspace                   # 全部通过
```

数量以输出为准。别把"clippy 干净"当成事实写进任何地方。

真实窗口的 GUI 验收不在 `cargo test` 里，用 `tools/*.ps1` 手动跑；
证据落点由每条脚本的 `-OutRoot` 决定（默认 `.verify/runs/…` 或 `target/verify/…`，

### 第一次使用

1. 启动编辑器，菜单 **项目 → 新建项目…**
2. 输入项目名，选择（或新建）一个**空目录**作为项目根

6. 关掉编辑器重新打开，**项目 → 打开项目…** 选同一个目录，编辑结果应当完全一致

## 架构一览

四层，依赖严格单向：

```text
editor_app  ──>  editor_ui  ──>  editor_core  ──>  scene_doc
    │                                                  ▲
    └──────────────────────────────────────────────────┘
             （scene_bridge 只用 scene_doc + Bevy）
```

| 层 | 生命周期 | 是否依赖 Bevy | 为什么这样分 |
| --- | --- | --- | --- |
| `scene_doc` | 随磁盘 | **否** | 持久化格式必须独立于引擎类型，否则引擎换代就毁掉用户资产 |
| `editor_core` | 随编辑器会话 | **否** | 编辑器逻辑要能在无 GPU、无窗口的 CI 里被完整测试 |
| `editor_ui` | 随帧 | **否**（只依赖 egui） | 界面逻辑（树构建、菜单可用性）用纯函数表达才可测 |
| `editor_app` | 随进程 | 是 | 只有真正需要窗口与渲染的部分才碰 Bevy |

> 这条主线之外还有几个卫星 crate，它们不参与"编辑闭环可测"这件事：
> `savegame` 与 `runtime_protocol` 是**叶子**（自己谁也不依赖，所以上面的
> `editor_core` / `editor_ui` 能干净地用上存档与调试协议）；
> `breeze_debug_adapter` 是唯一碰 Bevy 的那个，装在**用户的游戏**里；
> `bsn_bridge` 只依赖 `scene_doc`，把官方场景格式接进文档模型；
> `gui_probe` 是验收工具，产品运行不依赖它；
> `breeze_runtime` 反过来依赖 `editor_app` 的装配路径 —— 这是「薄壳」的代价，
> 见「它现在不能做什么」。

### 三个关键数据流

**① 编辑**：界面产出意图 → 执行器 → 唯一修改入口

```text
用户点击
  → 面板把操作翻译成 UiAction 排进队列
  → editor_app 的 执行动作队列 在下一帧统一执行
  → 编辑器状态::执行(命令)   ← 唯一允许改文档的入口
      ├─ 克隆文档
      ├─ 在克隆上应用命令（失败则正本一字未动）
      └─ 成功才提交回正本 + 记录撤销条目
```

**② 保存**：三段式原子写盘

```text
写 <场景>.tmp  ──►  原文件改名 <场景>.bak  ──►  .tmp 改名到原文件  ──►  删除 .bak
   失败就放弃          失败就清理 .tmp 返回      失败就把 .bak 搬回来
读取顺序：原文件 → .bak → .tmp（每个候选都必须完整解析成功）
```

**③ 运行**：单向桥接，物理隔离

```text
场景文档  ──[构建世界]──►  独立的 Bevy World（运行时宿主持有）
    ▲                            │
    │                            │  只读地取统计数据
    └────── 绝不自动回写 ─────────┘
```

停止运行时整个 `World` 被丢弃，运行时修改不可能回写文档 ——
这不是靠约定，而是靠**两份数据**。

细节见 [`docs/架构设计.md`](docs/架构设计.md)。

## 场景文件格式

场景是 RON 文本，扩展名 `.scene.ron`。当前 `格式版本` 是 **2**（1 → 2 改的是
预制件嵌套实例的语义，见 `scene_doc::document` 的版本历史注释）。
下面这份和磁盘上的真实文件同构，只是删掉了一些节点：

```ron
(
    格式版本: 2,
    元数据: (
        场景标识: "8f1c2d3e-...",
        场景名: "主关卡",
        保存时间: Some(1792259048),
    ),
    // 全局环境：等于默认值的字段不会落盘，所以这里可能整段缺席。
    环境: (
        背景颜色: (
            红: 0.42,
            绿: 0.53,
            蓝: 0.66,
            透明度: 1.0,
            是_srgb: true,
        ),
    ),
    实体表: {
        "11111111-1111-1111-1111-111111111111": (
            标识: "11111111-1111-1111-1111-111111111111",
            名称: "玩家",
            父实体: Some("22222222-2222-2222-2222-222222222222"),
            次序: 0,
            变换: Some((
                平移: (100.0, 50.0, 0.0),
                旋转: (0.0, 0.0, 0.0, 1.0),
                缩放: (2.0, 2.0, 1.0),
            )),
            组件: [
                (
                    类型名: "Sprite",
                    属性: {
                        "颜色": 颜色((红: 0.25, 绿: 0.5, 蓝: 0.75, 透明度: 1.0, 是_srgb: true)),
                        "水平翻转": 布尔(true),
                        "贴图": 资源((路径: "assets/textures/hero.png")),
                    },
                ),
            ],
        ),
    },
    顶层顺序: ["22222222-2222-2222-2222-222222222222"],
    // 场景引用到的资源汇总，导出打包按这一张表收文件。
    资源表: {
        "assets/textures/hero.png": (
            路径: "assets/textures/hero.png",
        ),
    },
)
```

几个刻意的设计：

- **实体表是扁平的，层级靠 `父实体` 字段表达**。改层级、重命名、撤销
  都是线性操作，而不是在嵌套树上做最坏情况的子树搬移
- **`次序` 唯一**，决定兄弟间的绘制与遍历顺序
- **`格式版本` 放在最前面**，便于工具在不完整解析的前提下判断能否处理
- **默认值不落盘**（`skip_serializing_if`）：`环境`、`资源表`、`编辑器隐藏`
  在没有被改过时压根不出现在文件里，场景 diff 只有真正的改动
- **字段顺序稳定**（内部用 `BTreeMap`），保存不会产生无意义的文本 diff
- **未知组件与未知属性原样保留**，所以版本升级不会静默丢数据

- `场景保存后重新打开数据保持一致` —— 逐字段比对而非整体比较，失败能定位到层
- `保存失败时原文件不被破坏` —— 注入写入失败，断言原文件内容一字未改

## 设计上的取舍

这些决定都有代价，写在这里是为了让后来者知道"为什么不能随便改"。

### 1. 场景文档用扁平实体表，而不是嵌套树

**换来**：改层级 / 重命名 / 撤销都是线性操作；按 ID 查找是 O(log n)。
**代价**：层级是隐式的，必须靠 `校验()` 保证父实体存在、无环、次序唯一。

### 2. 撤销用全量快照 + 命令重放，而不是反向操作

**换来**：正确性只依赖"文档能 Clone"与"命令能 apply"这两件已有测试覆盖的事。
**代价**：内存。用 64 MiB 字节预算约束，超预算从最旧一端丢弃条目
（只影响能撤销多少步，不影响撤销是否正确）。

### 3. 视口 = Bevy 渲到纹理 + egui 叠加层，而不是让游戏相机直接接管窗口

**换来**：预览跑在真正的渲染管线里（`RenderTarget::Image` → `painter().image` 铺进面板），
所以材质、灯光、阴影、glTF 动画、HUD、粒子在编辑器里就是它们在游戏中的样子；
而网格、选中框、操纵器、悬浮栏这些编辑元素仍由 `editor_ui` 画在最上层，
不依赖游戏相机、每帧确定可见。轨道相机只属于编辑器，改取景不会改文档。
**代价**：两块渲染要维护同步 —— 预览的实体是从文档投影出来的一份独立树，
文档改了要按代次重建；贴图缓存、材质代次、变更检测都得显式管，
少推进一次代次就会出现"改了材质视口没反应"这类缺陷（这类 bug 真实出现过并修过）。
**边界**：预览**不是**把项目自己的 System 跑起来看效果，那是 PIE 与「运行项目」的职责。

### 4. 组件注册表驱动 Inspector，而不是 `bevy_reflect`

**换来**：`Color`、`Handle<T>`、枚举、以及游戏自己的组件都能编辑，
不要求它们派生 `Reflect`；新增组件不改一行 UI 代码。
**代价**：每个类型要写一次 `导出 / 实例化` 转换。
**反射仍有用**：ECS 调试器（只读浏览运行时世界）会直接走 `bevy_reflect`，
因为那里不存在"转换回文档"的需求。

### 5. 界面不直接改编辑器状态，而是产出 `UiAction`

**换来**：面板可单测；避免在遍历容器时修改容器；将来加"关闭前询问保存"
只需在执行器插入判断。
**代价**：多一层间接，动作要在下一帧才生效（实际上用户感知不到）。

### 6. 中文标识符

按项目约定，自定义类型、函数、字段、局部变量用中文，
Rust / Bevy / 外部库 API 保留英文原名。
文件名、模块名、crate 名用英文 —— 这不只是风格考虑：
Cargo 的 `package.name` 与文件名限制为 ASCII，因此这是唯一可行的组合。

### 第三方组件不在这份许可覆盖范围内

本仓库**随附**下列第三方资产，它们保留各自的原始许可与作者署名：

| 组件 | 位置 | 许可 | 主要约束 |
| --- | --- | --- | --- |
| Noto Sans SC 子集（界面中文字体，缺了它汉字全是 `□`） | `crates/editor_ui/assets/fonts/` | SIL Open Font License 1.1（原文随附 `OFL.txt`） | 再分发须保留许可证原文；不得单独售卖字体本身 |
| Tabler Icons（面板图标 PNG） | `crates/editor_ui/assets/icons/` | MIT（版权与全文见同目录 `LICENSE`） | 保留版权与许可声明 |

也就是说：拿走本项目时，**代码**按双许可任选其一，**字体与图标**继续受各自条款约束。
`Cargo.toml` 里的依赖许可由各自上游决定，不受本文件声明影响。
