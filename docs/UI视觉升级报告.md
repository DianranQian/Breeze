## 2. 三个设计方向与最终选择

对比页：`style-explorer.html`（四栏：改造前基线 / A / B / C），并归档为
[docs/验收证据/56_设计方向_三方向对比.png](验收证据/56_设计方向_三方向对比.png)。
候选源码在 `explore/a.html`、`explore/b.html`、`explore/c.html`，清单 `explore/manifest.json`。

| 方向 | 骨架与视觉重心 | 字体 | 色彩身份 | 判定 |
| --- | --- | --- | --- | --- |
| A 专业深色工作台 | 单行命令栏（品牌+菜单+模式分段）→ 工作区条 → 工具栏 → 三栏停靠；视口是唯一主角 | 12.5px 正文，600 字重只给对象名与分组标题，数值等宽右对齐 | 石墨底（#0D0F11/#16191C）+ 青绿强调（#6FD3C7），强调只用于选中/焦点/运行态 | **采用** |
| B 雾白精密工作室 | 左侧 56px 模式导轨 + 文档式标题行；检查器以分节浅灰条组织 | 12.5px 正文 / 15px 标题，等宽字给坐标与路径 | 暖白纸面（#F4F2EE/#FBFAF8）+ 深靛（#2F4D8F），靠细线与字重分级 | 色彩与分节方式被吸收进浅色主题 |
| C 沉浸式创作工作台 | 视口铺满整窗，悬浮胶囊命令条 + 左侧图标轨 + 玻璃检查器 + 左下树抽屉 | 12px 正文 / 20px 画面标题 | 近黑（#141210）+ 琥珀（#E9A35C），玻璃层带 14px 模糊 | 结构不采用（会削弱停靠与面板调整），视口优先的思路被吸收 |

**为什么选 A：**

1. 微风已有成熟的 `egui_dock` 停靠架构、四套工作区与五种主模式。C 的浮动玻璃方案会把「停靠/拆分/折叠/调整尺寸」这些已交付能力变成次要路径，属于用视觉取舍换功能退化。
2. A 的结构与现有架构一一对得上（modebar → 工作区分段 → 工具栏 → 停靠区），可以**分批落地、逐批编译验证**，回归面最小。
3. 三个方向共用同一套语义色槽位，因此 A 的语言能在深/浅/高对比三套主题里原样成立 —— B 的浅色方案因此被吸收为浅色主题的取值依据，而不是另立一套。

差异检验：A/B/C 的首屏骨架、字体尺度、色彩身份、主视觉四项中，任意两者至多一项相同；C 的块面分布与 A 明显不同（A 是「细边栏+中央大块」，C 是「整屏留白+悬浮小块」）。

### 3.3 第二轮：从"修饰"改为"换语法"

第一轮完成后（把每块面板修干净）观感仍然像"同一套灰色方盒子换了个配色"，因此做了一次**视觉语法层面**的替换，而不是继续加装饰：

| 改变 | 之前 | 之后 | 为什么 |
| --- | --- | --- | --- |
| 顶部层级 | 菜单栏 + 模式栏 + 工作区栏 + 工具栏，四层横条（约 130px） | 菜单栏 + 导航行（模式‖工作区）+ 工具栏，三层（约 102px） | 模式与工作区都是"当前上下文"，并排比堆叠省一次视线移动，也把高度还给视口 |
| 控件边框 | 每个按钮一圈 1px 灰边，密集处像"一排格子" | 默认无边框：底色分档 + 悬停才出现底色；边框只留给输入框与聚焦态 | 边框是普通桌面软件最显眼的"廉价感"来源 |
| 停靠标签 | 每个标签一块灰底 + 圆角 + 常亮 ✕ | 标签与面板同色，激活态用 2px 强调下划线；关闭只保留面板级 ✕ | 双 ✕ 相邻易误关；整块高亮看起来像"被按下的按钮" |
| 视口叠加层 | 带描边和填充的工具条压住左上角 | 透明浮层：状态点 + 读数 + 无边框开关 | 让视口重新成为"空间"，而不是"带框的画布" |
| 视口网格 | 固定亮度的密集方格，浅色下尤其抢眼 | 中心清楚、边缘退后；次线按屏幕像素密度自动隐藏（深色 12px / 浅色 24px 阈值） | 网格是参考线，不是纹理 |
| 检查器数值 | 三个独立 DragValue，精度 0.0/1.00/288.00 混用 | 一组数值一个浅底容器，固定两位小数、轴字母带轴色、标签右对齐成一条竖线 | 读一行数值时不需要重新解析轴与单位 |
| 重复入口 | 工具栏与视口各有一套"网格/坐标轴/包围框" | 只保留视口内一份，工具栏只放动作 | 同一功能两个入口会让用户怀疑它们不是一回事 |
| 字号与呼吸 | 13 / 控件 26 / 圆角 4 | 13.5 / 控件 30 / 圆角 6，按钮内边距更大 | 稠密工具也需要可读的行高，否则像表格 |

### 3.4 第三轮：视口工具回到视口里（按 Godot / Blender 的参照）

反馈指出"选择/移动/旋转/缩放的位置不对"。对照 Godot 与 Blender 的做法可以确认这是结构问题，不是审美差异：

| 参照 | 变换工具位置 |
| --- | --- |
| Godot 4 | 视口正上方一条独立工具条（选择/移动/旋转/缩放 + 视口菜单） |
| Blender 4 | 视口左缘一条竖向工具栏（T 键可收起） |
| Unity | 左上角工具条，紧贴 Scene 视图 |

共同点：**这些工具作用于画面，所以跟着视口走**。本轮取 Godot 的做法（顶部横条），因为底部已有读数条，横条不会与它打架。

具体改动：

| 之前 | 之后 |
| --- | --- |
| 全局工具栏最左边是 选择/移动/旋转/缩放 + 适应窗口 + 重置视图 + 网格/坐标轴/包围框 | 这些全部移进**视口的顶部工具条**（半透明浮层，贴着视口顶边）；全局工具栏只留 运行/编辑/实体/面板 |
| 2D 的视口显示开关在视口左上角，3D 的轨道控制在全局工具栏 | 2D 与 3D 使用**同一套**视口工具条：左端变换工具，中段 适应窗口 / 重置视图（3D 为重置视角/聚焦选中），右端显示开关 |
| 全局工具栏随主模式变化，切模式时工具位置跳变 | 全局工具栏不再随视口模式变化，位置稳定 |
| 视口底部提示与读数挤在左下角 | 读数留左下，操作提示移到右下 |

区域标识（`tool_select` / `tool_move` / `tool_rotate` / `tool_scale` / `btn_fit_2d` / `btn_reset_view_2d`）在**新位置**继续记录，因此自动验收仍然按真实矩形点击这些按钮。

### 3.5 第四轮：视口工具条改为纯图标

文字版工具条把视口上方切成了"四个词 + 两个图标 + 四个开关"，和 Godot 那条纯图标工具条不是一种语言。本轮改为：

| 项 | 做法 |
| --- | --- |
| 变换工具 | 新增 Tabler 风格图标：`pointer`（选择）、`arrows-move`（移动）、`rotate-clockwise`（旋转）、`resize`（缩放），在视口工具条里做成**图标分段按钮**（28×28，选中=强调淡底+强调描边，悬停=中性底） |
| 名称与快捷键 | 全部移入悬停提示（"移动（W）"），工具条上不再出现文字 |
| 适应窗口 / 重置视图 | 与工具按钮共用同一套尺寸与底色规则，视觉重量一致，不再"工具是块、动作是字" |
| 显示开关 | 保留"文字 + 状态点"：它们是开关而不是工具，需要能读出当前是开还是关 |
| 图标来源 | 手写 SVG（Tabler 3.49 的 24×24 / stroke 2 坐标系），用现有 `icon_bake` 烘焙成 32×32 PNG，仍走"白色描边 + 主题 tint"，没有新增图标库 |

工具条收尾：把一条工具条整理成**三组同语法胶囊**（工具 / 视口动作 / 显示开关）。
第一版只给工具组套了胶囊，中间两个裸图标看起来"没有归属"，右侧开关又长成一排文字；
三组各自成胶囊之后节奏一致。次要动作（适应窗口 / 重置视图）的按钮与图标都比主工具小一档
（24/14 对 29/16），保证视口工具条上只有一个视觉主角。

工具组补齐的分组容器（Godot 风格）：

- 四个变换工具收进一个**胶囊容器**（面板色底 + 1px 边框 + 8px 圆角），边界本身说明"四选一"；
- 原有的整条工具条底色去掉，画面上只留下两个可见分组：工具胶囊 与 右侧显示开关；
- 胶囊用**面板色**而不是叠加色：深色下叠加色与视口底色几乎同值、浅色下叠加色近白，都会让分组"消失"（第一版实测确实看不见，因此改成面板色 + 边框）。

视口底部读数条（选项 A）：

- 读数与右下操作提示改用与工具条同一套"细胶囊"容器：半透明面板色、圆角 6、无描边；
- 去掉重复的状态点（词条文案本身以「●」开头，再手绘一个点会变成两个）；
- 该改动只影响绘制，不涉及配置与协议。

浅色主题的输入边界（选项 B）：

- 深色下输入框不用描边（底色 `#0D0F11` 压在面板 `#16191C` 上已经够区分）；
- 浅色下输入框是纯白、面板是暖白，去掉边框后读数与标签会连成一片 ——
  因此只给**浅色**补一道 1px `边框` 描边（`视觉规范::输入框外框` / `输入框框架`），
  深色保持无边框，避免退回"一排小方格"。
- 实体名不套输入框：它是这一屏的标题，加底色会让最高层级看起来像表单第一行。

未新增任何第三方依赖；未改 Bevy/egui/egui_dock 版本；未改 crate 名、包名或内部 id。

| 项 | 值 |
| --- | --- |

| 面板内边距 | 左右 10、上下 8 |

### 4.3 字体与图标

- 沿用现有字体资产：Ubuntu-Light + Noto Sans SC 子集（GB2312 全集）+ Hack 等宽，不引入新字体。
- 层级只靠三档字号 + 字重：Heading = 基础+6（19），正文/按钮 13，节标题 12.5，辅助 11，等宽 12；不再用彩色文字堆层级。
- 图标继续用项目自带 Tabler PNG 染色体系（`图标库`），没有新增图标库；场景树按 `节点类型` 给不同图标（容器/精灵/房屋/树叶/模型…），不用同一个空心方块。
- 图标只出现在「有明确语义的高频动作」上：模式切换、变换工具、新建/删除、运行、面板开关；不给每个按钮硬塞图标。

### 4.4 交互状态

| 状态 | 表现 |
| --- | --- |
| 默认 | 按钮 `#22272C` 底 + 1px `#262C32` 边 |
| 悬停 | 提亮一档底色 + 强调色描边（`expansion=0`，不放大） |
| 按下 | 再深一档底色 + 强调亮描边 |
| 打开/保持 | 激活底色 + 强边框 |
| 选中（列表/分段） | 选中底色 + 2px 强调竖条（列表）或强调描边（分段） |
| 键盘焦点 | 与悬停同色但保留描边，文本光标使用主题色 |

## 8. 已解决的视觉问题与仍存在的不足

**已解决**

- 顶部 chrome 的重复感：四行改成「一层标题区 + 布局条 + 工具栏」，模式与工作区用同一套分段语法但底色分层区分职责。
- 层级缺失：字号阶梯、字重、分组细线、属性网格让「标题 / 分组 / 属性名 / 数值」四层可辨。
- 选中反馈弱：场景树与检查器都有明确的主选中表达，视口选中框用主题选择框色。
- 控件状态不全：默认/悬停/按下/打开/选中/禁用六态统一由主题给出，不再只美化静态默认态。
- 视口被 UI 挤压：提示改为浮层，视口多出约 30px 高。
- 浅色主题可读性：暖白底 + 深青强调，不再是「白底浅灰字」。

**仍存在的不足（不夸大覆盖范围）**

1. **节点编辑器不存在**：代码库中没有节点图/图形工作流界面（只有脚本、构建、运行、时间轴、Agent 面板），本轮没有虚构该界面。
2. **脚本 / 构建 / 运行 / 时间轴 / Agent 五个面板只继承了全局样式**，没有逐个重排信息层级；它们沿用原有布局，只获得新的字号、间距、四态与颜色。
3. **3D 的 Gizmo 与手柄颜色**没有重新调过；视口工具条的四工具已收进胶囊容器，但"适应窗口 / 重置视图"仍是裸图标，与胶囊之间只靠分组细线分隔。
4. **停靠标签栏的折叠箭头与关闭符号**仍是 `egui_dock` 自带的字形，未替换成项目图标。
5. **主题编辑器的外观滑块需要滚动才能看全**，窗口高度是按内容压缩后的折中值。
6. **1024 宽、中文、侧栏全开**时，场景树头部仍可能挤压场景名（已截断，但空间确实紧）。
7. **高对比度主题**只跟随新体系调了网格与分隔线，没有为它单独设计一套版式。
8. 对话框（新建项目、关于、项目设置、帮助）只继承主题与间距，没有逐个重做版式。
9. **去掉边框之后，浅色主题的数值输入组边界偏弱**：白底输入框叠在暖白面板上，只靠 1px 的明度差区分。需要在下一次迭代里给浅色主题单独加一层极浅描边（不影响深色）。
10. **工作区切换并入导航行后，右侧空间依赖窗口宽度**：1280 以下时工作区标签开始被挤压（已截断，但没有"⋯"收纳）。
11. **窄窗口（1024×700）工具栏右侧图标仍越界**：工具栏没有横向滚动/收纳策略，右侧几个面板入口在窄档被窗口边缘切掉，停靠标签也只显示前几个。这是既有布局约束，本轮没有引入溢出菜单。
12. **视口叠加层在窄窗下会被截断**（"Collisio…"）：叠加层与读数共用一行，宽度不够时只能截断。

## 9. 结论

本轮在真实代码里落地了一套可复用的视觉规范（语义色 + 尺度 + 六态 + 复用件），并把它应用到了最高频的四处界面：整体框架、场景树、检查器、视口提示与主题编辑器。编译、全量测试与真实截图均通过；改动集中在 `editor_ui`，没有触碰数据模型、存档格式、协议与快捷键。
