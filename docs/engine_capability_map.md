# 微风（Breeze）引擎能力地图

> **本文档是审计结果，不是愿望清单。**
>
> 审计基线：`7b2fa5b` + 未提交工作区（2026-10-21 夜，含并行的 UI 升级与瓦片地形线）。
> 审计方式：逐 crate 读模块头与公开 API、grep 关键能力、跑 `cargo test --workspace`
> （基线 700+ 测试全绿）、跑 `gui_probe` 真实窗口验收、核对 `docs/验收证据/`。
>
> 成熟度口径见 §0。**任何条目只要没有真实数据模型 + 用户入口 + 运行时/持久化行为
> + 可复核证据，就不得标 M4 以上。**

## 0. 成熟度模型

| 等级 | 含义 | 判定要点 |
| --- | --- | --- |
| M0 | 未审计 | 代码现状不明，不能下结论 |
| M1 | 已确认缺失 | 找不到可用实现 |
| M2 | 数据/API 层存在 | 有结构、有底层函数，但没有可完成工作的界面或闭环 |
| M3 | 可操作但有关键缺口 | 有界面/动作，缺持久化、引用同步、错误恢复或运行验证之一 |
| M4 | 工作流闭环 | 创建→编辑→保存→重开→运行/诊断可用，有自动测试；GUI 证据可能不完整 |
| M5 | 闭环 + 证据齐全 | M4 + 自动化 + 真实 GUI/运行时证据 + 错误路径验证 |

实现形态：**核心原生 / Bevy 适配 / 第三方插件 / 外部工具 / 暂缓 / 技术边界**。

## 12. 本轮审计纠正的认知

1. **资源管理不是"完全没做"**：项目层已有 `移动资源`、`删除资源`、`检查资源引用`，
   场景文档已有 `改资源路径`；缺的是**引用位置索引、跨场景同步、用户入口与守卫**。
   本轮补齐了这四件事，E3–E6 从 M1/M2 推进到 M4。
2. **文档落后于代码**：`项目现状总览.md` 记录 377 个测试、6 个 crate；实际已有
   10 个 workspace 成员、700+ 测试、资源导入清单、打包、动画、物理、运行时调试 2.0。
   因此本轮新增能力地图，并明确标注旧文档只作历史线索。
3. **`gen_messages.py --check` 当前失败**，但失败条目来自**并行 UI 工作线**尚未提交的
   新文案（`inspector_panel.rs`、`viewport_panel.rs`），不是本轮引入；本轮新增文案
   已全部进入 `messages.tsv`。
4. **`cargo fmt --all` 会碰到并行工作线的未提交文件**（`gizmo.rs`、`inspector_panel.rs` 等）。
   本轮已发生一次全仓格式化，只改了排版；后续批次应改为按文件 `rustfmt`。
