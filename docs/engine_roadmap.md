## 3. 里程碑详细定义

### R0（本轮，已完成）资源引用与安全操作闭环

| 项 | 内容 |
| --- | --- |
| 目标 | 让"删除/重命名资源"从不可用变成**有引用守卫、跨场景同步、可撤销**的工作流 |
| 交付 | `scene_doc::asset_refs`（位置级引用视图）、`editor_core::asset_index`（跨场景索引 + 删除守卫 + 未使用/缺失）、`asset_ops`（移动文件 + 原子写回 + 回滚）、重命名/删除对话框、`资源使用报告`、`改资源路径` 命令 |
| 验收 | 5 条集成测试 + 6 条索引单测 + 4 条文档视图单测 + 5 条 `asset_ops` 单测；真实 GUI 截图（删除被阻止、重命名预填）|
| 证据 | `.verify/asset_ops/` |
| 已知限制 | 其它场景的改写直接写盘、不进撤销栈；不支持删除目录；不能改扩展名 |

### R1 资源稳定标识（UID）—— 已完成

- **目标**：给每个导入资源生成 UUID，场景引用同时记录路径与 UID；
  文件移动后即使路径对不上，也能按 UID 找回。
- **状态**：已完成（2026-10-22）。`asset_uid` 表 + `.breeze/asset_uids.ron`、
  保存场景时写入 UID、重命名/删除同步表、打开场景按 UID 修复并强制置脏。
- **遗留**：打开但从未保存的场景没有 UID；原生工程不落盘；无文件系统监听。
- **依赖**：R0 的索引与移动流程。
- **验收**：
  1. 旧场景（无 UID）打开后自动补全并保存；
  2. 手工把文件改到另一目录（不经过编辑器）→ 打开项目时按 UID 重连引用并给出提示；
  3. 同一 UID 出现在两个不同路径时报告冲突，不静默选择。
- **风险**：场景格式变化需要迁移函数（已有版本字段）。

### R1.5 自动保存与恢复点 —— 已完成

- **目标**：编辑中周期写恢复点；异常退出后下次启动提示恢复。
- **状态**：已完成（2026-10-22）。恢复点写 `.breeze/recovery/`（索引 + 内容），
  30 秒间隔且必须有修订变化；保存成功后清理；启动只提示"比磁盘新"的恢复点；
  恢复装进编辑器并强制置脏，不写盘。
- **遗留**：不监听崩溃瞬间（最多丢 30 秒）；"稍后处理"只关提示不删文件；
  未做"恢复点自动过期清理"（保留上限 5 个已足够）。
- **依赖**：`scene_doc::storage` 原子写、项目根目录。

### R3 动画事件 —— 已完成

- **目标**：动画在关键帧之外能触发真实事件（音效/逻辑），并能在时间轴上编辑。
- **状态**：已完成（2026-10-22）。事件结构 + 左开右闭/循环回绕的区间触发；
  时间轴事件行（三角形标记、双击添加、右键选类型/删除）；播放时写日志，
  音效类型在编辑器里真实试听；撤销走动画独立历史。
- **遗留**：事件名称暂时取"项目里第一个音频"或占位名，没有专门编辑框；
  逻辑/自定义事件只记录，由游戏侧消费。
- **验收**：6 条单测 + 5 条集成 + GUI 截图（`.verify/anim_events/`）。

### R4 资源引用查找与定位 —— 已完成

- **目标**：从资源直接回答"谁在用它"，并能跳到具体实体。
- **状态**：已完成（2026-10-22）。资源右键「查找引用」→ 跨场景列出
  `场景 / 实体 / 组件.属性`；「定位」同场景直接选中，跨场景先打开场景
  （有未保存修改时拒绝，不替用户丢数据）。
- **遗留**：未做图形化依赖图；跨场景跳转要求先保存。
- **验收**：5 条集成测试 + GUI 截图（`.verify/find_refs/`）。

### R5 3D 拾取与多选 —— 已完成（部分）

- **目标**：三维视口能批量选、能按遮挡关系选对。
- **状态**：已完成（2026-10-22）。`picking3d` 负责候选与决策：屏幕距离优先、
  相差 ≤3px 时用相机深度兜底；Shift 追加、Ctrl 切换。
- **遗留**：框选（矩形拖拽）未做；没有射线-网格精确求交（仍是点到屏幕距离）；
  `gui_probe` 的指针注入不带修饰键，多选点击路径没有真实指针证据。
- **验收**：8 条单测 + 3D 多选 GUI 截图（`.verify/multi_select/`）。

### R6 3D 框选 —— 已完成

- **目标**：在三维视口拖动矩形批量选中。
- **状态**：已完成（2026-10-22）。`picking3d::屏幕矩形`（两点归一化、
  4px 有效阈值、包含判定）+ 框选命中；`viewport3d` 按"操纵器 > 框选 > 相机"
  的优先级处理左键拖动，松手才改选择集。
- **过程中修掉的真问题**：最初在 `drag_started()`（按下即触发）就清空选择，
  导致普通单击被吞掉；改成"真正移动后才进入框选、松手才提交"。
- **遗留**：框选按投影点而非屏幕包围盒；按钮与相机的修饰键组合尚未细分。
- **验收**：11 条单测 + 真实指针拖拽（选择数 0→3，日志含"执行选择动作 设为(3 项)"）。

### R7 多选对齐与分布 —— 已完成

- **目标**：框选/多选之后能批量整队，而不是逐个改数值。
- **状态**：已完成（2026-10-22）。`editor_core::arrange` 纯函数（6 种对齐、
  水平/垂直等距分布）；2D 视口多选时显示浮动对齐条；批量改动合并为
  **一条** `批量设变换`，一次撤销整批退回。
- **取舍**：只在 2D 显示（3D 的 AABB 需要真实网格尺寸，宁可先不显示也不给错位按钮）。
- **验收**：8 条单测 + 4 条集成（对齐、分布、少于两个、已对齐无撤销步）+ GUI 截图。

### R8 场景实例刷新 —— 已完成

- **目标**：改了源场景后，已经摆进关卡的实例能一次更新，而不是删掉重摆。
- **状态**：已完成（2026-10-22）。`instance::刷新实例` 保留实例根的
  父级/次序/变换/名称，整棵子树替换为源场景当前内容；动作层包成一条
  `设为快照` 命令，撤销恰好一步。菜单「场景 → 用源场景刷新实例」。
- **遗留**：实例仍是**复制式**，不会自动跟随源场景；没有覆盖值（override）
  与"还原到源"的单属性操作。
- **验收**：3 条单元 + 3 条集成 + 真实 GUI 刷新（名称/位置保留、来源可见）。

### R9 运行时资产规模 —— 已完成（部分）

- **目标**：运行时面板能回答"游戏里加载了多少资产、规模多大"。
- **状态**：已完成（2026-10-22）。协议新增 `资产统计`（网格/顶点/索引、
  图片/像素、音频/字节、字体数），带 `serde(default)` 兼容旧游戏端；
  适配器从真实 `Assets<T>` 采集；面板显示"资产规模"。
- **明确不做**：不展示"内存占用"。RSS/显存不可从 Bevy 可靠获取，
  把可测量的规模说成内存是误导。
- **遗留**：无 CPU/GPU 分解；demo 用 `MinimalPlugins`，GUI 里看不到非零资产。
- **验收**：适配器 3 条单测（真实 Assets 夹具）、协议 2 条（旧格式兼容、
  往返）、E2E 真实握手通过。

### R10 动画事件编辑 —— 已完成

- **目标**：事件从"只能加"变成"能改名、换类型、填参数"，并一步撤销。
- **状态**：已完成（2026-10-22）。时间轴点击事件三角选中（外圈高亮），
  编辑区显示类型/名称/参数/时间；空白名称与失效下标被拒绝并告警。
- **取舍**：事件没有稳定 ID，选中用下标；更新后重排序可能移动下标，
  因此更新成功即清除选中（宁可让用户重选，也不编辑错行）。
- **验收**：2 条新集成（改名+撤销、拒绝空名/失效下标）+ GUI 截图。

### R11 打开场景时补全 UID —— 已完成

- **目标**：让"打开但从未保存"的旧场景也具备 UID 回连能力。
- **状态**：已完成（2026-10-22）。打开场景时对齐文档与标识表：
  文档缺 UID 就补，表缺条目就登记；只在**确有变化**时标脏并提示
  "已为 N 个资源补全稳定标识（UID），保存场景后生效"。
- **修掉的计数 bug**：`对齐文档标识` 原来只在"表里新建条目"时计数，
  而打开项目时同步已经把表填满了，于是"文档补齐了 UID"返回 0，
  既不提示也不标脏——补了等于没补。现在两个方向都计入。
- **验收**：3 条集成（打开标脏、保存后重开不脏、无资源场景不脏）+
  GUI 证据（控制台 12 个资源、状态栏未保存）。

### R2 3D 编辑闭环

- 3D 框选与多选、射线求交拾取、gizmo 与多选联动、撤销步合并。
- 验收：GUI 真实指针拖拽 + Inspector 数值同步 + 一步撤销。

### R3 Play-in-Editor

- 运行时世界渲染到视口（或独立纹理），暂停冻结画面，停止恢复编辑预览。
- 验收：运行时画面与编辑态不同（像素断言）、实体数与文档一致、停止后恢复。

### R4 诊断与性能

- `cargo check --message-format=json` 诊断接入代码面板（已有构建诊断，补代码内标记）；
- 性能：帧耗时分解、运行时系统耗时（Bevy 可获取部分）、资源/纹理数量；
- 明确标注"不可观测"的指标，不伪造。

### R5 内容生产扩展

- 2D 地形接入碰撞与导航（等并行线落地）；
- 动画事件轨、UI 主题资产、音频总线；
- 粒子基础发射器（先 2D，再 3D）。

## 4. 持续项（每个批次都要做）

1. 能力地图/差距矩阵与代码同步（发现不符就改文档，不把错误认知留档）；
2. `cargo test --workspace`、定向 clippy、`gen_messages.py --check`；
3. 至少一个真实 GUI 场景（`gui_probe`）截图 + 机器可读报告；
4. 新动作必须有构造点（`动作可达性` 测试会拦）；
5. 新界面文案必须进 `messages.tsv` 并重新生成词表。

## 5. 已知跨工作线约束

- 并行线正在做 UI 视觉升级与瓦片地形（`tile_terrain.rs`、`视觉规范.rs`）。
