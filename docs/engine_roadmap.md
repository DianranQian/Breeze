## 3. 里程碑详细定义

### R0（本轮，已完成）资源引用与安全操作闭环

| 项 | 内容 |
| --- | --- |
| 目标 | 让"删除/重命名资源"从不可用变成**有引用守卫、跨场景同步、可撤销**的工作流 |
| 交付 | `scene_doc::asset_refs`（位置级引用视图）、`editor_core::asset_index`（跨场景索引 + 删除守卫 + 未使用/缺失）、`asset_ops`（移动文件 + 原子写回 + 回滚）、重命名/删除对话框、`资源使用报告`、`改资源路径` 命令 |
| 验收 | 5 条集成测试 + 6 条索引单测 + 4 条文档视图单测 + 5 条 `asset_ops` 单测；真实 GUI 截图（删除被阻止、重命名预填）|
| 证据 | `.verify/asset_ops/` |
| 已知限制 | 其它场景的改写直接写盘、不进撤销栈；不支持删除目录；不能改扩展名 |

### R1 资源稳定标识（UID）—— 已完成

- **目标**：给每个导入资源生成 UUID，场景引用同时记录路径与 UID；
  文件移动后即使路径对不上，也能按 UID 找回。
- **状态**：已完成（2026-10-22）。`asset_uid` 表 + `.breeze/asset_uids.ron`、
  保存场景时写入 UID、重命名/删除同步表、打开场景按 UID 修复并强制置脏。
- **遗留**：打开但从未保存的场景没有 UID；原生工程不落盘；无文件系统监听。
- **依赖**：R0 的索引与移动流程。
- **验收**：
  1. 旧场景（无 UID）打开后自动补全并保存；
  2. 手工把文件改到另一目录（不经过编辑器）→ 打开项目时按 UID 重连引用并给出提示；
  3. 同一 UID 出现在两个不同路径时报告冲突，不静默选择。
- **风险**：场景格式变化需要迁移函数（已有版本字段）。

### R1.5 自动保存与恢复点 —— 已完成

- **目标**：编辑中周期写恢复点；异常退出后下次启动提示恢复。
- **状态**：已完成（2026-10-22）。恢复点写 `.breeze/recovery/`（索引 + 内容），
  30 秒间隔且必须有修订变化；保存成功后清理；启动只提示"比磁盘新"的恢复点；
  恢复装进编辑器并强制置脏，不写盘。
- **遗留**：不监听崩溃瞬间（最多丢 30 秒）；"稍后处理"只关提示不删文件；
  未做"恢复点自动过期清理"（保留上限 5 个已足够）。
- **依赖**：`scene_doc::storage` 原子写、项目根目录。

### R3 动画事件 —— 已完成

- **目标**：动画在关键帧之外能触发真实事件（音效/逻辑），并能在时间轴上编辑。
- **状态**：已完成（2026-10-22）。事件结构 + 左开右闭/循环回绕的区间触发；
  时间轴事件行（三角形标记、双击添加、右键选类型/删除）；播放时写日志，
  音效类型在编辑器里真实试听；撤销走动画独立历史。
- **遗留**：事件名称暂时取"项目里第一个音频"或占位名，没有专门编辑框；
  逻辑/自定义事件只记录，由游戏侧消费。
- **验收**：6 条单测 + 5 条集成 + GUI 截图（`.verify/anim_events/`）。

### R4 资源引用查找与定位 —— 已完成

- **目标**：从资源直接回答"谁在用它"，并能跳到具体实体。
- **状态**：已完成（2026-10-22）。资源右键「查找引用」→ 跨场景列出
  `场景 / 实体 / 组件.属性`；「定位」同场景直接选中，跨场景先打开场景
  （有未保存修改时拒绝，不替用户丢数据）。
- **遗留**：未做图形化依赖图；跨场景跳转要求先保存。
- **验收**：5 条集成测试 + GUI 截图（`.verify/find_refs/`）。

### R5 3D 拾取与多选 —— 已完成（部分）

- **目标**：三维视口能批量选、能按遮挡关系选对。
- **状态**：已完成（2026-10-22）。`picking3d` 负责候选与决策：屏幕距离优先、
  相差 ≤3px 时用相机深度兜底；Shift 追加、Ctrl 切换。
- **遗留**：框选（矩形拖拽）未做；没有射线-网格精确求交（仍是点到屏幕距离）；
  `gui_probe` 的指针注入不带修饰键，多选点击路径没有真实指针证据。
- **验收**：8 条单测 + 3D 多选 GUI 截图（`.verify/multi_select/`）。

### R6 3D 框选 —— 已完成

- **目标**：在三维视口拖动矩形批量选中。
- **状态**：已完成（2026-10-22）。`picking3d::屏幕矩形`（两点归一化、
  4px 有效阈值、包含判定）+ 框选命中；`viewport3d` 按"操纵器 > 框选 > 相机"
  的优先级处理左键拖动，松手才改选择集。
- **过程中修掉的真问题**：最初在 `drag_started()`（按下即触发）就清空选择，
  导致普通单击被吞掉；改成"真正移动后才进入框选、松手才提交"。
- **遗留**：框选按投影点而非屏幕包围盒；按钮与相机的修饰键组合尚未细分。
- **验收**：11 条单测 + 真实指针拖拽（选择数 0→3，日志含"执行选择动作 设为(3 项)"）。

### R7 多选对齐与分布 —— 已完成

- **目标**：框选/多选之后能批量整队，而不是逐个改数值。
- **状态**：已完成（2026-10-22）。`editor_core::arrange` 纯函数（6 种对齐、
  水平/垂直等距分布）；2D 视口多选时显示浮动对齐条；批量改动合并为
  **一条** `批量设变换`，一次撤销整批退回。
- **取舍**：只在 2D 显示（3D 的 AABB 需要真实网格尺寸，宁可先不显示也不给错位按钮）。
- **验收**：8 条单测 + 4 条集成（对齐、分布、少于两个、已对齐无撤销步）+ GUI 截图。

### R8 场景实例刷新 —— 已完成

- **目标**：改了源场景后，已经摆进关卡的实例能一次更新，而不是删掉重摆。
- **状态**：已完成（2026-10-22）。`instance::刷新实例` 保留实例根的
  父级/次序/变换/名称，整棵子树替换为源场景当前内容；动作层包成一条
  `设为快照` 命令，撤销恰好一步。菜单「场景 → 用源场景刷新实例」。
- **遗留**：实例仍是**复制式**，不会自动跟随源场景；没有覆盖值（override）
  与"还原到源"的单属性操作。
- **验收**：3 条单元 + 3 条集成 + 真实 GUI 刷新（名称/位置保留、来源可见）。

### R9 运行时资产规模 —— 已完成（部分）

- **目标**：运行时面板能回答"游戏里加载了多少资产、规模多大"。
- **状态**：已完成（2026-10-22）。协议新增 `资产统计`（网格/顶点/索引、
  图片/像素、音频/字节、字体数），带 `serde(default)` 兼容旧游戏端；
  适配器从真实 `Assets<T>` 采集；面板显示"资产规模"。
- **明确不做**：不展示"内存占用"。RSS/显存不可从 Bevy 可靠获取，
  把可测量的规模说成内存是误导。
- **遗留**：无 CPU/GPU 分解；demo 用 `MinimalPlugins`，GUI 里看不到非零资产。
- **验收**：适配器 3 条单测（真实 Assets 夹具）、协议 2 条（旧格式兼容、
  往返）、E2E 真实握手通过。

### R10 动画事件编辑 —— 已完成

- **目标**：事件从"只能加"变成"能改名、换类型、填参数"，并一步撤销。
- **状态**：已完成（2026-10-22）。时间轴点击事件三角选中（外圈高亮），
  编辑区显示类型/名称/参数/时间；空白名称与失效下标被拒绝并告警。
- **取舍**：事件没有稳定 ID，选中用下标；更新后重排序可能移动下标，
  因此更新成功即清除选中（宁可让用户重选，也不编辑错行）。
- **验收**：2 条新集成（改名+撤销、拒绝空名/失效下标）+ GUI 截图。

### R11 打开场景时补全 UID —— 已完成

- **目标**：让"打开但从未保存"的旧场景也具备 UID 回连能力。
- **状态**：已完成（2026-10-22）。打开场景时对齐文档与标识表：
  文档缺 UID 就补，表缺条目就登记；只在**确有变化**时标脏并提示
  "已为 N 个资源补全稳定标识（UID），保存场景后生效"。
- **修掉的计数 bug**：`对齐文档标识` 原来只在"表里新建条目"时计数，
  而打开项目时同步已经把表填满了，于是"文档补齐了 UID"返回 0，
  既不提示也不标脏——补了等于没补。现在两个方向都计入。
- **验收**：3 条集成（打开标脏、保存后重开不脏、无资源场景不脏）+
  GUI 证据（控制台 12 个资源、状态栏未保存）。

### R12 游戏存档体系 —— 已完成

- **目标**：给游戏提供与编辑器场景保存**独立**的运行时存档，玩家能存、能读、
  能迁移、坏了能回退。
- **为什么不是 Play-in-Editor**：核验发现运行时宿主是裸 `World`（`scene_bridge`
  里没有相机、渲染目标、调度器），编辑器内嵌真实游戏画面需要另一套渲染/进程
  架构，成本 L 且容易做成"静态截图冒充实时"。存档体系能复用已有原子写与
  版本迁移经验，成本 M，且是发布游戏必需的一块。详见本节末尾的判定表。
- **状态**：已完成（2026-10-22）。
  - 新 crate `crates/savegame`：槽位、元数据、格式版本、原子写、备份回退、
    损坏检测、迁移、槽位名白名单（防目录穿越）；9 条单测。
  - 示例游戏 `examples/savegame_demo`：六个可执行场景（init/play/load/verify/
    corrupt/future），真实写盘、真实读回，退出码可断言。
  - 编辑器「资源 → 存档槽位」只读浏览器：列出槽位元数据与损坏项，**不删改**玩家存档。
- **明确不做**：编辑器写存档、云同步、加密、自动备份轮转。
- **验收**：9 单测 + 3 集成（扫描/无项目/刷新）+ 6 场景端到端 + GUI 截图。

#### 为什么本轮没选 Play-in-Editor

| 子能力 | 现状 | 证据 |
| --- | --- | --- |
| 1. 启动外部游戏进程 | **已完整实现** | `editor_core::run_entry`、`项目运行管理器`、`tests/运行时调试桥` |
| 2. 连接外部调试桥 | **已完整实现** | `runtime_protocol` + `breeze_debug_adapter` + E2E 握手测试 |
| 3. 编辑器内真正的游戏运行视口 | **尚未实现** | 运行时宿主只有裸 `World`（`scene_bridge.rs` 的 `运行时宿主::世界`），无相机/渲染目标/调度；预览渲染目标只服务编辑态 `preview.rs` |
| 4. 运行视口的输入/暂停/停止 | **部分实现**（针对外部进程） | 运行工作台可启动/停止/重跑；内嵌视口的焦点与鼠标捕获不存在 |
| 5. 编辑态/运行态隔离 | **已实现**（外部进程天然隔离） | 运行使用 `启动快照`，编辑文档不被游戏改动 |
| 6. 调试/日志/ECS 统一工作流 | **已完整实现** | 运行面板 + 诊断中心 + 运行时 ECS 面板 |

结论：唯一缺失的是第 3 项，但它恰恰是最贵的一环（渲染架构），且第 4 项依赖它。
按"本轮能否形成真实可验收闭环"的标准，先做存档体系；PIE 保留为 R13，
需要先做一次最小渲染实验再动工。

### R13 Play-in-Editor 最小实时渲染实验 —— 已完成（原型）

- **目标**：回答"微风能否以可维护方式把独立运行的 Bevy 游戏世界实时渲染到
  编辑器内部"，并给出可运行原型，而不是设计稿。
- **结论**：**可以**，路径是"运行时实体活在编辑器 App 的 World 里 +
  `RenderLayers` 隔离 + `RenderTarget::Image` + egui 纹理显示"。
  原型已真实跑通：画面持续更新、鼠标输入可改变画面、停止后可重启、
  编辑态场景文档零污染。
- **实现**：`crates/editor_app/src/pie_proto.rs`（独立文件，不改既有渲染链路；
  仅 `plugin.rs` 注册一行插件）。环境变量 `BEVY_STUDIO_PIE=1` 启动，
  `BEVY_STUDIO_PIE_SCENARIO=restart` 触发"第 120 帧停止、第 150 帧重启"。
- **验收**：
  - 5 条纯逻辑单测（自动移动撞墙掉头、指针优先、键盘覆盖、dt 夹取、加速）；
  - 3 条集成（启动生成相机/地面/方块且相机真的渲染到 Image、停止清空、
    连续三次启停后计数递增、原型实体不进场景文档）；
  - GUI 单会话日志 `帧 30..240` 的方块 x 连续变化（连续帧证据）；
  - 帧 90 与帧 300 两张截图的 PIE 区域有 **1.570%** 像素差异（块位置不同）；
  - `gui_probe drag` 注入真实鼠标：日志出现 `指针 Some(0.5097)`、
    `输入驱动 48 帧`，方块 x 从 −1.499 被拉到 3.000；
  - 停止/重启场景：`已停止（本次运行 120 帧）` → `已启动（第 2 次）` → 继续推进；
  - 三次 GUI 运行证据里 `document_dirty=false`、`实体 0`，编辑态未被污染。

#### 为什么是这条路径（方案对比，均有代码级依据）

| 方案 | 结论 | 依据 |
| --- | --- | --- |
| A. 复用编辑器 App 渲染体系（运行时实体在主 World + 独立层 + 独立渲染目标） | **可行，已采用** | `preview.rs` 早已用 `RenderTarget::Image` + `EguiUserTextures` 把 2D 场景画进 egui；PIE 只是换一个 `RenderLayers` 层与一张独立纹理 |
| B. 独立 Bevy App 或独立窗口 | **否决** | 一个进程内再起 `App` 会再起 winit 事件循环；且第二个 `App` 的 `World` 不会被主 `RenderApp` 提取，画面无处可渲染；窗口方案也不是"嵌入编辑器" |
| C. 独立渲染进程 + 回读传图 | **否决** | 实时画面必须每帧 GPU→CPU→GPU 传输，这正是任务书明确禁止的"伪实时"；延迟与带宽成本与收益不成比例 |

#### 本轮**没有**做（不要误读为已完成）

- 暂停/步进：只有启动/停止/重启；
- 鼠标捕获与输入焦点管理：按键需要窗口聚焦，没有"点击画面即捕获"；
- 运行时调试接入：PIE 原型与 `runtime_protocol` 无关，运行时 ECS 面板读的仍是外部进程；
- 多相机/多视口、运行中热重载、资产加载：原型只用纯色 Sprite，不涉及 `AssetServer`。

#### 完整 PIE 的后续阶段（依赖顺序）

1. **R13.1 输入与焦点** —— 已完成，见下节；
2. **R13.2 生命周期**：暂停/单步/重启时保留相机与纹理、只重建实体；
3. **R13.3 资产**：运行世界接 `AssetServer`（与编辑器同一个 `AssetPlugin`），
   让 PIE 能显示真实模型与贴图；
4. **R13.4 调试接入**：把 `runtime_protocol` 的检查目标从"外部进程"扩展到"进程内运行世界"；
5. **R13.5 编辑态隔离策略**：明确规定"运行中禁止保存到原文档"，或按 Godot 的
   "运行副本 + 停止即丢弃"语义。

### R13.1 PIE 输入捕获与焦点路由 —— 已完成

- **目标**：让 PIE 从"能看"变成"能玩"——点击画面把输入交给游戏，Esc 收回，
  且编辑器快捷键不会和游戏抢同一批按键。
- **状态**：已完成（2026-10-22）。
- **焦点状态机**（`crates/editor_app/src/pie_input.rs`）：`无会话 / 未捕获 /
  已捕获 / 挂起`，转换只有四个入口（开始会话、结束会话、请求捕获、
  释放/失焦/恢复/目标失效），记录会话号、鼠标捕获、键盘路由、窗口活跃与原因。
  视口 UI、快捷键、运行生命周期都**只调用**这个状态机，不各自维护布尔值。
- **点击捕获**：只有命中 PIE 图像矩形的点击才请求捕获；`CursorGrabMode::Locked`
  + 隐藏光标（**系统级**锁定，不是 egui 矩形内锁定）。
- **Esc 释放**：捕获时 Esc 由游戏侧消费并调用 `释放(用户按Esc)`；未捕获时
  Esc 仍归编辑器的"取消选择"，两者互斥。
- **键盘路由**：`路由键盘` 是纯函数，捕获后移动/加速/动作归游戏；
  `actions::处理快捷键` 是**唯一**门控点，捕获时跳过全部快捷键，只放行 F7（停止）。
- **鼠标**：捕获态只用 `MouseMotion` 相对位移（绝对坐标在指针锁定后无意义），
  未捕获态保留原来的"拖拽 → 指针目标"链路；两条链路互斥。
- **生命周期**：停止立即释放并清空 PIE 自己的输入（不碰全局键盘状态）；
  重启进入新会话号且回到未捕获；窗口失焦 → 挂起并释放，恢复后**不**自动重新捕获。
- **验收**：
  - 11 条单元测试（路由、Esc、重复释放、失焦、停止、重启、目标失效、提示词）；
  - 6 条集成测试（其中一条用真实 `ButtonInput` 走到路由结果）；
  - 全量 `cargo test --workspace` 1169 通过 / 0 失败；
  - **真实 GUI**：`gui_probe run --pie-keys` 注入真实鼠标点击 → 日志 `已捕获`；
    真实按住 `A`/`D` → 日志 `键盘 左=true` / `键盘 右=true` 且方块位置改写；
    真实 Esc → `未捕获` 且后续帧按键全 `false`；
    Ctrl+F1 在捕获期被拦（日志 `PIE 捕获中：编辑器快捷键已停用`，帮助未打开）；
    Esc 后 F1 打开帮助（证据区域出现 `float_help`）；
    停止 → `无会话` → 重启 → `会话 2 · 未捕获`。
- **已知限制**：
  - 方向键（VK 0x25/0x27）经 `SendInput` 注入后 Bevy 收不到（补了
    `KEYEVENTF_EXTENDEDKEY` 仍无效）；WASD 可正常验证，游戏本身两条都支持。
  - 真实 Alt+Tab 失焦未做 GUI 实测（Windows 前台锁使脚本无法稳定让窗口
    失去/获得焦点）；该路径由单元测试覆盖，属于"未执行"而不是"已验证"。
  - 捕获期间快捷键整体停用，只放行 F7；没有做"按游戏需求选择性放行"。

### R13.2 PIE 运行生命周期（暂停/继续/单步）—— 已完成

- **目标**：暂停只冻结**游戏模拟**，不冻结编辑器；单步只推进一次模拟。
- **状态**：已完成（2026-10-22）。
- **状态模型**：`Pie运行状态 { 已停止, 运行中, 已暂停 }`（枚举，不是两个布尔），
  转换只有 `启动_实现 / pie暂停 / pie继续 / pie请求单步 / 停止_实现` 五个入口；
  非法操作返回 `false` 且不制造"虚假暂停会话"。
- **隔离方式**：`推进原型` 是唯一的游戏模拟入口，暂停时它直接返回；
  egui 绘制、输入焦点、PIE 渲染、证据采集都与暂停无关，照常运行。
- **时间隔离**：不碰全局 `Time`。PIE 用自己的 `模拟累计秒`，运行时按
  `delta_secs().clamp(0, 0.1)` 累加，暂停时不累加。
- **执行粒度**：一次单步 = **一个固定 1/60 秒模拟步**（`单步步长秒`），
  不是一帧渲染。单步与常规模拟走同一条 `推进原型` 路径，只换步长来源。
- **单步语义**：`待单步` 用计数而非布尔（连点两次 = 执行两次）；
  每次 `取本帧步长` 最多消费一个；停止时丢弃未执行请求。
- **验收**：
  - 14 条单元测试（含暂停后 60 帧零推进、单步恰好一次、连点两次执行两次、
    未运行时暂停/单步被拒、停止丢弃、暂停不改文档、巨大 dt 不瞬移）；
  - 5 条集成测试（真实 `World` + `run_system_once` 跑 `推进原型`：
    暂停 20 帧零推进、单步恰好一帧且仍暂停、继续恢复、停止不推进、大 dt 夹住）；
  - 全量 `cargo test --workspace` 1183 通过 / 0 失败；
  - **真实 GUI**：`BEVY_STUDIO_PIE_SCENARIO=lifecycle` 在第 90 帧暂停、
    120/150 各单步一次、180 继续；日志逐条可见
    `[生命周期] 第 90 帧：暂停` → `PIE 单步执行 #1（帧 89 → 90）` →
    `PIE 单步执行 #2（帧 90 → 91）` → `[生命周期] 第 180 帧：继续`；
    暂停期间帧号停在 90，恢复后继续增长到 172。
- **未做**：
  - **时间缩放未实现**：本轮优先保证暂停/继续/单步的时钟语义正确；
    加倍率会让"暂停时倍率是否生效""单步是否受倍率影响"两个歧义同时出现，
    成本高于收益，留给后续阶段。
  - 按钮点击未做程序化注入：PIE 面板是应用内 egui 窗口，控件矩形不进入
    区域证据；因此生命周期**调用链**由环境变量脚本验证，按钮可用性由截图目视确认。
  - 暂停时**不**释放鼠标捕获（焦点与暂停是两个独立维度），这一点在代码注释与
    文档中写明。
