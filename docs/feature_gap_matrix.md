# 微风 功能差距矩阵（对照 Godot / Unity / Unreal）

> 本轮审计基线：`7b2fa5b` + 工作区。成熟度与 ID 见
> [`engine_capability_map.md`](./engine_capability_map.md)。
>
> **读法**：这里比较的是**工作流是否闭环**，不是"两边的功能列表谁更长"。
> Godot/Unity/Unreal 的列只写"该引擎在它的目标用户里已经成熟的能力"，
> 不代表微风必须全部实现。差距列分四类：
>
> - **通用缺口**：普通 2D/3D 游戏开发者都会需要，应排进路线图；
> - **专业扩展**：面向重度专业用户，可按需建设；
> - **外部工具**：成熟引擎也是靠 DCC/第三方完成的，微风应做集成而非重写；
> - **技术边界**：受 Bevy 0.20 渲染栈、平台授权或产品定位限制，明确记录替代方案。

## 2. 逐个关键差距

### 2.1 资源引用体系（本轮已补齐主体）

| 能力 | Godot | 微风 | 结论 |
| --- | --- | --- | --- |
| 删除被引用资源时阻止并列出引用 | 有（`ResourceLoader` 依赖 + 编辑器警告） | **本轮实现**：跨场景、位置级、坏场景也拒绝 | 对齐 |
| 重命名/移动后自动改引用 | 有（`.godot` 导入缓存 + UID） | **本轮实现**：文件移动 + 其他场景原子写回 + 当前文档走命令可撤销 | 对齐（除 UID 重定向） |
| 未使用资源报告 | 有（"Orphan Resource" 提示） | **本轮实现**：`资源使用报告` | 对齐 |
| 稳定 UID 重定向 | 有 | 字段存在但从不生成 | 下一批（E7） |

### 2.2 3D 编辑（M3 → M4 的关键缺口）

| 缺口 | 为什么阻塞工作流 | 依赖 |
| --- | --- | --- |
| 3D 多选/框选 | 无法一次摆一组物体 | 屏幕空间选择集 |
| 3D 拾取用射线求交而不是屏幕最近点 | 遮挡时会选错 | `Camera3d` 视锥数学 |
| 材质/灯光编辑入口 | 只能改组件数值，看不到材质资产 | 资源层材质类型 |
| 网格诊断（法线/切线/UV） | 导入异常无法定位 | 网格读取 API |

### 2.3 运行与预览（最大用户可感缺口）

| 缺口 | 现实替代 | 成本 |
| --- | --- | --- |
| Play-in-Editor（视口里跑游戏） | 目前"运行项目"会起独立进程，带运行时调试桥 | L：需要运行时世界与渲染隔离 |
| 暂停/单步游戏逻辑 | 运行时调试可观察但不可控 | M：需要游戏侧配合 |
| 热重载 | 无 | L：Bevy 资产热重载可部分复用 |

### 2.4 明确属于"技术边界"的能力

| 能力 | 边界原因 | 替代方案 |
| --- | --- | --- |
| 主机平台发布 | 需要平台授权 SDK | 记录为不支持；用桌面平台验证工作流 |
| Web/移动发布 | Bevy 0.20 可行但未在本机验证；需要 wasm 工具链 | 下一阶段做一次真实 `wasm32` 构建实验再承诺 |
| 高端 GPU 特效图 | 需要自定义 render graph 与节点编译 | 先做参数化粒子/后处理预设 |
| 原生多窗口 | `bevy_egui 0.43` 不分发 `ViewportCommand::CreateWindow` | 应用内浮窗 + 工作区预设 |
| LSP 全家桶 | 依赖 rust-analyzer 进程、增量同步、坐标映射 | 先用 `cargo check --message-format=json` 诊断 |

## 3. 差距排序（影响 × 依赖）

| 排名 | 差距 | 影响 | 依赖 | 建议批次 |
| --- | --- | --- | --- | --- |
| 1 | 资源 UID 与移动重定向（E7） | 中 | E3/E4 已就绪 | 下一批 |
| 2 | 3D 多选 + 射线拾取（D3） | 高 | 无 | 下一批 |
| 3 | Play-in-Editor 渲染（Q5） | 高 | 运行时宿主 + 预览管线 | 下两批 |
| 4 | 自动保存/崩溃恢复（X2/B10） | 高 | 场景存储已就绪 | 下两批 |
| 5 | 2D 地形接入物理/碰撞（F4/J1） | 中 | 并行线 tile_terrain | 串行等待 |
| 6 | 游戏 UI 专用编辑视图（M3） | 中 | `ui_layout` 已就绪 | 中期 |
| 7 | 动画事件轨（I3） | 中 | `animation` 轨道模型 | 中期 |
| 8 | 音频总线/空间音频（N2） | 低 | Bevy audio | 中后期 |
| 9 | 粒子系统（O1） | 中 | 需要渲染扩展 | 后期 |
| 10 | 性能分析器（S1–S3） | 中 | 需要 runtime 指标 | 后期 |

## 4. 不追赶的能力（明确不做）

- 完整 DCC 建模、网格布尔、UV 展开：交给 Blender，微风只做导入与重导入。
- 自研物理后端：2D 用 Rapier，3D 评估后再引入单一后端，避免双后端。
- 在线资产商店、账号与云同步：不属于当前产品阶段。
- 通用节点式可视化脚本：优先把 Rust/Bevy 原生开发体验做好。
