# 技能：Bevy 架构与 AI 提效审查 (触发词: 执行架构审查)

## 触发条件
仅当用户明确发送“执行架构审查”或“读取该技能执行审查”时启动。
未触发时，本文件不参与任何日常代码生成与修改。

## 核心纪律（只读模式）
1. 严禁修改任何业务/生产代码，先出诊断报告。
2. 严禁全库通读。必须忽略 `target/`、`.verify*/`、`.tmp/`、`.bevy_studio/` 等目录。
3. 所有结论必须附带文件路径和行号证据。
4. 优先排查：是否手搓轮子而没有使用成熟 crate（如 UI、拾取、序列化等）。

## 审查任务
1. 工作区自检：扫描根目录是否有 `.verify_v*`、`.tmp` 等历史污染，必须在报告开头警告。
2. 开发地图：按 Bevy Plugin/System/Component 划分模块，标注（已开发/未开发/半成品/废弃）。
3. 耦合簇诊断：识别超长函数（巨型 System）、超大共享状态（大 Resource 且被多处 &mut）、硬编码注册（加一个面板动多处）。列出最小读取集。
4. 重构优先级：区分高收益低风险、高收益高风险任务，强调按小步快跑、可回滚的原则。

## 输出模板（必须严格遵循）
A. 诊断结论（10条内，直击痛点）
B. 开发地图表
C. 耦合簇清单
D. AI Agent 最小读取策略
E. 优先级列表
F. 下一步行动清单与风险应对
