# 示例项目为什么"不能看"，以及根因修复

> 记录时间：2026-10-18
> 涉及：`examples/2d_demo`、`examples/3d_demo`、`TileTerrain`、`Primitive3d`

## 0. 一句话结论

示例难看的根因不在素材，也不在配色，而在**编辑器的视觉层只有一种原语**：

```text
Sprite = 一张贴图四边形（或一个 glTF 场景）
```

原项目的画面都不是这样搭出来的：

- 2D 地面 = **逻辑地形网格 + 双网格自动瓦片 + 多材质分层合成**；
- 3D 竞技场 = **受光的长方体 + UV 重复 + 阴影**。

用一张四边形去复刻这两种东西，只能得到"把整张 4×4 过渡图集塞进一格"的
花斑，或者"把地面/围墙拍成平面贴图"的纸片舞台。素材再换、颜色再调，
都改变不了这个结构性错配。

## 1. 2D 示例的失败路径

### 1.1 第一阶段：整张图集当一格

`透明到浅草地.png` 这类资产是 **64×64 = 4×4 张 16px 瓦片**，
每张图表达"一种材质在 2⁴ 种四角组合下长什么样"。
原项目按四角掩码从里面取 **一张 16px 瓦片**。

旧示例直接把整张 64×64 图当"一格草地"缩放显示。于是每一格都是
16 个不同过渡形状拼成的花斑；地图看起来像随机色块。

### 1.2 第二阶段：烘焙成一张 PNG

后来改成"用 Python 把整张地图拼好，导出 PNG，场景里放一个精灵"。
画面确实完整了，但它把原项目的整套系统**删掉了**：

| 能力 | 原项目 | 烘焙 PNG |
| --- | --- | --- |
| 改一格地形 | 改数据，重新合成 | 重跑外部脚本，换图 |
| 换一套瓦片图集 | 换目录即可 | 重新烘焙 |
| 变体概率 / 每格像素 | 参数 | 固定死在图里 |
| 纹理分辨率 | 按需 | 固定，缩放会糊 |
| 数据体积 | 48×32 个字符 | 一张大图 |

这不是优化，是把编辑器能做的事搬到了编辑器外面。

### 1.3 根因

`editor_app::preview` 的投影规则是"有 `Sprite` 组件才渲染"，
渲染方式是"一张贴图四边形"。文档里没有任何东西能表达：

- 一块地形由哪些逻辑格组成；
- 每个视觉瓦片四角是谁；
- 该去哪个图集的哪一张取像素；
- 图层先后与变体选择。

## 2. 3D 示例的失败路径

原项目 `tps_arena/src/plugins/level.rs` 构建的是：

- 48×48×0.6 的地面长方体；
- 四面 48×8×0.6 的围墙长方体；
- 受光 PBR 材质，UV 重复；
- 23 件真实 glTF 掩体 + 真实角色；
- 方向光与阴影。

旧示例只有：

- 9 块 8×8 的 **unlit** 贴图四边形当地面（24×24，原项目的一半）；
- 两面 unlit 四边形当墙；
- 6 件道具、3 个角色。

于是它必然看起来像"一块漂浮的纸片地板 + 两面纸墙"：
没有厚度、没有 UV 重复、没有受光、没有阴影、没有封闭空间。

### 2.1 根因

同样是视觉原语缺失：文档里没有"几何体 + 材质"这一层。
`Sprite` 的引擎实现是 unlit quad，做不出 PBR 地面，也接不住阴影。

## 3. 根因修复：给编辑器补上两种一等视觉原语

### 3.1 `TileTerrain`（2D）

场景里存**参数 + 数据路径**，不存地面图片：

```text
TileTerrain
├─ 地形文件   assets/.../*.terrain.ron   （宽度/高度/地表/覆盖 字符网格）
├─ 图集目录   assets/.../瓦片            （10 张四角图集 + 1 张变体表）
├─ 显示尺寸   (3072, 2048)
├─ 每格像素   64
└─ 变体概率   0.35
```

`crates/editor_app/src/tile_terrain.rs` 在加载时按原项目规格合成：

```text
字符网格 ──► 逻辑格材质
         ──► 每张视觉瓦片四角掩码（POS / CORNER_BIT）
         ──► 图集取 16px 瓦片（整格按概率抽手绘变体）
         ──► 按 DRAW_SURFACES 分层合成（后画的抢像素）
         ──► 最近邻放大到「每格像素」
```

规则逐条对应原项目：

| 规则 | 原项目出处 |
| --- | --- |
| 图集 4×4 乱序索引 | `src/mapgen/atlas.rs` 的 `POS` |
| 四角位权 `[TL,TR,BR,BL]=[8,4,1,2]` | `CORNER_BIT` |
| 地表图层顺序 | `DRAW_SURFACES` |
| 整格变体 0.35 概率 | `VARIANT_FILE` / `balance.ron` |
| 道路/耕地在全部地表之后 | `bake.rs` 的 `Layer::ALL` |

**地面图不是资产，是每次加载算出来的结果。**

### 3.2 `Primitive3d`（3D）

```text
Primitive3d
├─ 形状       Cuboid / Plane
├─ 尺寸       (48, 0.6, 48)
├─ 贴图       floor.png
├─ 贴图重复   (6, 6)
├─ 受光       true
└─ 双面       false
```

预览生成真正的 `Mesh3d` + `StandardMaterial`：

- 长方体有厚度，四面墙形成封闭空间；
- `uv_transform` 把 256px 纹理重复 6×6，地面网格保持 1m 尺度；
- `unlit: false` + 方向光 `shadow_maps_enabled = true`，接收光照与阴影；
- `cull_mode` 按 `双面` 决定，薄墙可双面。

3D 示例的 23 件掩体位置逐条照抄原项目 `掩体布局`，
所以它演示的是原关卡的空间关系，不是"随便摆几个模型"。

### 3.3 配套改动

- 视口包围框：`TileTerrain` 用显示尺寸，`Primitive3d` 按"地面取 xz / 墙取 xy"；
- 2D 视口消费 `视口命令`：修掉"2D 模式 toolbar 的适应窗口点了没反应"；
- 3D `适应场景` 改为按 FOV 与宽高比求距离，不再用"对角线 × 1.6"；
- 打开 2D 项目自动框住整张地图；3D 不自动拉全景（48×48 拉全景后角色只剩十几像素）；
- 组件注册表、运行时桥接、BSN 提取器同步注册两个新组件；
- Inspector 由注册表自动获得字段，未新增任何硬编码 UI。

## 4. 怎么重新生成

```powershell
# 1) 2D：复制原项目图集、生成字符网格与道具（不烘焙地面）
python tools/build_xiuxian_demo.py `
    --source "C:\Spaces\Share\10_Code\10_Bevy\修仙冒险游戏\assets" `
    --out examples/2d_demo/assets/xiuxian `
    --layout examples/2d_demo/layout.json

# 2) 两个场景
cargo run -p editor_core --example generate_demo_project
```

2D 的 `assets/xiuxian/瓦片/` 是原项目素材的原样副本；地面在编辑器里现算。

## 5. 已知边界（不要再误解成"渲染坏了"）

| 项 | 现状 |
| --- | --- |
| 地形刷子 | 没有。改 `.terrain.ron` 的字符网格，保存后预览按 mtime 重烘 |
| 地形生成器 | 数据由 `tools/build_xiuxian_demo.py` 离线生成；编辑器负责**程序化渲染**，不内置噪声地图生成器 |
| 山崖岩壁层 | 未接入。原项目的岩壁依赖 16×32 塔块与连续台地，直接用山丘掩码会碎成红点；示例用岩石道具表现山脚 |
| 动画 | 角色取的是静态帧；编辑器没有动画播放 |
| 运行时 | 运行时世界会持有 `TileTerrain`/`Primitive3d` 数据组件，但还没有把它们渲染成地面/网格；示例演示的是**编辑器预览** |
| 3D 近景 | 默认相机在中央主掩体附近；48×48 全景请点「适应窗口」 |
| 阴影性能 | 预览方向光开启了阴影贴图；低端 GPU 可在代码里关掉 |

## 6. 测试怎么守住它

| 测试 | 守住什么 |
| --- | --- |
| `tile_terrain::测试::四角掩码按位权组合` | 位权与角顺序 |
| `tile_terrain::测试::示例地形能烘焙出完整纹理` | 真实数据 + 图集 + 渲染规格，且**零透明缺口** |
| `示例项目::二维示例使用程序化瓦片地形` | 场景里必须是 `TileTerrain`，数据不是预烘焙 PNG |
| `示例项目::三维示例使用受光几何体与真实模型` | 23 件掩体 + 4 角色 + 5 个受光几何体 |
| `scene_bridge::测试::注册表与插入分支一一对应` | 新组件不会静默失效 |
