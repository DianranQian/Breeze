# 运行时调试协议与远程 ECS 检查器

> 这份文档描述**已经实现并经过真实端到端验收**的能力，不是规划。
> 验收命令与证据路径见文末。

## 1. 它解决什么问题

微风能启动一个原生 Bevy 游戏，但进程边界把它和游戏的 ECS 世界隔开了。
本功能建立一条**真实、默认只读、写入必须显式白名单**的数据通道：

```text
 微风（编辑器进程）                         用户游戏（原生 Bevy 进程）
 ┌──────────────────────┐   TCP loopback   ┌───────────────────────────┐
 │ 监听 127.0.0.1:0      │◄──── 连接 ───────│ Bevy调试插件                │
 │ 一次性令牌验证         │                  │ 后台线程（只排队，不改 ECS） │
 │ 版本/会话/长度校验      │─── 查询/快照 ───►│ 白名单检查器读取真实 World   │
 │ 请求编号 + 超时        │─── 白名单写入 ──►│ 主线程 PostUpdate 执行写入   │
 │ 冲突/幂等/未知结果      │◄── 真实结果 ─────│ 前后值/错误/序号/耗时        │
 └──────────────────────┘                  └───────────────────────────┘
```

### 明确的非目标

- 不共享 Bevy 内部类型：协议 crate `runtime_protocol` **不依赖 Bevy**。
- 不读取编辑器自己的“运行时世界”冒充游戏数据。
- 不提供任意文件读写、任意脚本执行、任意 Rust 代码执行命令。
- 不自动序列化任意 `Reflect` / 任意资源。
- 不允许任意反射写入：只有游戏端显式注册的**写入器 + 字段声明**可写。
- 不根据实体 ID、名称或 Transform 相似度自动推断编辑态关联。

## 2. 组件与边界

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 协议 | `crates/runtime_protocol` | 版本化消息、帧编解码、长度/分页/错误码，不依赖 Bevy |
| 游戏端适配器 | `crates/breeze_debug_adapter` | Bevy 0.20 插件、后台网络线程、白名单检查器、真实 ECS 采集 |
| 编辑器侧状态 | `crates/editor_core/src/runtime_debug.rs` | 实时/历史/过期/未接入/不兼容状态与 AI 上下文文本 |
| 编辑器侧连接 | `crates/editor_app/src/debug_bridge.rs` | loopback 监听、握手、心跳、请求关联、重连、生命周期 |
| 检查器 UI | `crates/editor_ui/src/runtime_panel.rs` | 实体列表、组件/Transform、资源、来源与可信度 |

## 3. 传输与协议

- TCP **仅 loopback**。编辑器绑定 `127.0.0.1:0`，把实际端口与随机令牌
  通过进程环境变量注入游戏；令牌不写入命令行。
- 帧格式：`4 字节大端长度 + UTF-8 JSON`。
- 单帧上限 4 MiB；每次最多 500 个实体；适配器每帧最多处理 12 个请求；
  编辑器最多 16 个在途请求；实体扫描上限 50,000（超出标记“已截断”）。
- 协议主版本必须相同，次版本不能高于本端；不兼容会收到明确错误码。
- 会话标识逐条校验：旧游戏/旧连接的消息不能污染新会话。
- 心跳双向存在：编辑器定期发送，游戏回应；任一侧超过窗口无消息即判定断线。

消息类别：

```text
client_hello / server_hello
request / response（世界概览、实体列表、实体详情、资源列表、资源详情、
                    世界快照、属性修改）
heartbeat / heartbeat_ack
notice（游戏退出、插件卸载、世界重建）
protocol_error（版本、认证、会话、长度、畸形、限流、超时）
```

## 4. 游戏端接入

```toml
[dependencies]
bevy_breeze_debug = { package = "breeze_debug_adapter", path = "…/crates/breeze_debug_adapter" }
```

```rust
App::new()
    .add_plugins(DefaultPlugins)
    .add_plugins(bevy_breeze_debug::Breeze调试插件::自动())
    .run();
```

没有 `BREEZE_DEBUG_PORT` 时插件完全停用：不建线程、不监听、不影响游戏。
需要检查自定义类型时显式注册只读提取函数：

```rust
Breeze调试插件::自动()
    .注册组件::<生命值, _>("生命值", |实体| {
        let Some(值) = 实体.get::<生命值>() else { return Vec::new() };
        vec![runtime_protocol::字段视图::浮点("当前", 值.当前.into())]
    })
    .注册资源::<游戏状态, _>("游戏状态", |世界| {
        世界.get_resource::<游戏状态>().map(|状态| vec![/* … */])
    })
```

**未注册的组件不会消失**：实体详情仍显示类型名，但明确标记“不支持检查”，
不伪造字段。`私有数据` 这类敏感组件只要不注册，就永远不会离开游戏进程。

### 4.1 安全属性编辑

写入不是“任意组件反射赋值”。游戏端必须显式注册**写入器**和**可写字段**
（含范围/是否允许分量写入）；未声明的字段即使存在于检查器中也不可写：

```rust
use bevy_breeze_debug::{可写字段声明, 写入结果};
use runtime_protocol::{字段值, 数值范围, 操作错误, 操作错误代码};

Breeze调试插件::自动().注册可写组件::<生命值, _, _>(
    "生命值",
    |实体| { /* 与只读检查器相同的字段提取 */ },
    |组件, 字段, 索引, 目标| match (字段, 目标) {
        ("当前", 字段值::浮点(值))
            if 索引.is_none() && 值.is_finite() && (0.0..=1000.0).contains(值) =>
        {
            let 前 = 组件.当前;
            组件.当前 = *值 as f32;
            Ok(写入结果 {
                修改前值: 字段值::浮点(前.into()),
                最终值: 字段值::浮点(组件.当前.into()),
            })
        }
        _ => Err(操作错误 {
            代码: 操作错误代码::值无效,
            消息: "当前必须是 0..=1000 的有限数".to_string(),
        }),
    },
    vec![可写字段声明::新建(
        "当前",
        Some(数值范围 { 最小: 0.0, 最大: 1000.0 }),
    ).只允许整体()],
);
```

内置 `Transform` 支持 `translation`、`rotation_quat`、`scale` 三个白名单字段。
旋转必须整体写入并在游戏端归一化；零长度四元数被拒绝。

写入协议还强制：

- 请求必须带 `预期原值`；游戏端当前值不一致时返回 `冲突`，且**不写入**；
- 请求带唯一 `请求标识`；重复重试返回第一次的真实结果（`重复请求=true`），
  不重复执行；
- 目标值必须通过游戏端写入器的范围/有限数检查；NaN/Infinity 一律拒绝；
- 实体销毁、组件移除、字段不存在、字段不可写都返回明确错误码；
- 只有明确的成功响应可以更新编辑器里的当前值；超时/断线只记录“结果未知”。

### 4.2 世界快照与差异

编辑器可以请求一份**有界**世界快照（最多 1000 个实体，含已注册资源），
快照记录项目/运行实例/会话/协议/Bevy 版本、序号、采集时间、实体/组件/
字段、资源、截断标记与估算大小。历史只保留最近 12 份，并有总大小上限。

差异只在**同一项目、同一运行实例**的两份快照之间计算，支持：

- 实体新增/消失；
- 组件新增/移除；
- 支持字段的旧值 → 新值；
- 资源字段变化；
- 不可比较项（字段缺失、支持级别变化、资源只在一侧）；
- 任一份快照被截断时，差异整体标记为“不完整”。

游戏重启后运行实例标识变化，旧快照被清空，不会与新世界混比。快照是
手动/低频操作，不每帧复制整个 ECS。

## 5. 编辑器端生命周期

1. 点“运行”前，编辑器创建**新的运行实例标识**与会话；
2. 启动时把端口/令牌/项目标识/运行实例标识注入游戏环境；
3. 后台线程 accept 后读 `client_hello`，校验令牌、项目、运行实例、版本；
4. 发送 `server_hello`，握手成功后立即拉取概览/实体/资源；
5. 每 2 秒自动刷新；实体被销毁或组件变化会在下一次快照中体现；
6. 游戏退出、用户停止、连接丢失都会把快照标记为**过期**，保留历史但不再实时；
7. 下次运行换新运行实例标识，旧会话数据被清空，不能冒充新运行。

界面状态与含义：

| 状态 | 含义 |
| --- | --- |
| 等待连接 | 编辑器已在 loopback 监听；游戏未接入插件时会一直等待，**不是失败** |
| 握手中 | 已接受连接，正在校验 |
| 已连接 | 真实握手完成，心跳正常 |
| 已断开 | 游戏退出/手动断开/心跳超时；历史快照保留但标记过期 |
| 不兼容 | 协议版本不匹配 |
| 未启用 | 当前运行目标不是带调试的游戏 |

## 6. 安全边界

- 只监听 `127.0.0.1`，适配器也拒绝非 loopback 配置；
- 一次性随机令牌，至少 16 字节；
- 每条消息校验版本、会话、长度；
- 只读白名单检查器；写入只走游戏端显式注册的写入器；
- 写入必须携带**预期原值**，游戏端按当前值做冲突检测；同值拒绝盲写；
- 每个写入请求带幂等键，超时重试只重放原结果，不重复执行；
- 网络线程只排队，写入在主线程 `PostUpdate` 的调试系统里执行；
- 请求限流、有界队列、有界缓存、有界分页；
- 不把普通 stdout/stderr 日志混进协议；
- 错误进入统一诊断中心，不静默失败；
- 超时/断线时编辑器只标记“结果未知”，绝不把未确认的写入显示成成功。

## 8. 已知边界

- 适配器当前只支持 Bevy **0.20**。0.19 需要独立适配器分支；协议 crate
  不依赖 Bevy，因此可以同时服务两者。
- 实体列表每次重新扫描世界（上限 50,000）。这是为了不维护一份可能与
  真实世界漂移的缓存；大规模世界后续可加增量快照。
- 写入白名单由游戏端决定；没有注册写入器的组件只能看，不能改。
- 快照是有界抽样（最多 1000 个实体），不是无限精确备份；截断时差异不完整。
- 编辑态关联只有用户显式指定才可靠，未关联时不会按名称/Transform 猜测。
