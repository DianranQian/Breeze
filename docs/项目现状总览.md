## 0. 状态分类口径

| 状态 | 含义 |
| --- | --- |
| **已实现且已验证** | 有生产代码，且有测试或真实 GUI 证据覆盖其核心行为 |
| **已实现但验证不足** | 有生产代码，但缺少集成/GUI 层面的验证，或只在单一场景验证过 |
| **部分实现** | 有真实基础能力，距离产品目标仍有明显缺口 |
| **尚未实现** | 代码中找不到可用实现（不含"按钮存在但无行为"） |
| **技术限制待确认** | 有调查结论，但尚未做出可复现原型或完整源码证据 |

"代码存在 / 测试通过 / GUI 验收通过"是三个不同层次，本文档对关键能力分别标注。

## 2. 五种主开发模式

模式定义：`crates/editor_ui/src/dev_modes.rs`（`开发模式` 枚举 + 每模式默认布局 + 模式/布局存档 v3）。
入口 UI：`dev_mode_bar.rs`（顶部 `2D | 3D | 代码 | 运行 | 资源` + 模式专用工具栏）。
切换逻辑：`界面状态::切换模式`（`state.rs`），每个模式持有独立的 `工作区集`。

### 2.6 模式之间的共享与边界

- **共享**：`编辑器状态`（文档/选择/撤销/日志）、主题、语言、缩略图、运行时诊断。
- **每模式独立**：一套 `工作区集`（布局）+ 该模式的 UI 私有状态（2D 相机 / 3D 轨道相机 / 脚本文档）。
- 切换模式**不重建**文档、不清选择、不改主题（测试 `切主题不改变工作区布局`、`切工作区不改变主题`、`切语言不改变主题与工作区`；模式切换本身尚无同名集成测试，见技术债务）。

### 3.3 布局约束

- 每个布局必须含视口或该模式主面板；`工作区集::修复` 会回退坏布局。
- GUI 验收按"布局轮廓"给不同阈值：通用/场景/调试视口宽度下限 30%，**资源模式 18%**，脚本模式允许视口非激活。
  - 资源模式的 29.1% 不是缺陷：该模式的设计目标就是资源浏览器占中央主体（≥25% 宽 × ≥55% 高），视口退居右上。判定见 `analysis.rs::布局轮廓` 与 `asset_browser_is_main_area`。

## 7. 自动化验收体系

### 7.1 采集（`editor_app::capture`）

- 触发：`BEVY_STUDIO_CAPTURE_PNG/JSON/FRAME/EXIT`，默认第 90 帧；
- 画面：`bevy::render::view::screenshot::Screenshot::primary_window()` 从**渲染目标**回读（非 GDI/PrintWindow）；
- 证据 JSON：模式、工作区、语言、主题（id/名称/明暗/三色）、UI 缩放、pixels_per_point、窗口尺寸、每块区域物理矩形、状态栏文案、可见面板键、图标数等；
- 退出：PNG 落盘后退 0；超时（600 帧）退 3。

### 7.2 判定（`gui_probe`）

- 窗口：`EnumWindows` 按进程号匹配 + per-monitor DPI 感知（否则 150% 缩放会误判）；断言标题可见、客户区与截图一致；
- 断言 32 项，分两类：**采集类**（尺寸/客户区/区域在画面内/窗口确认）与**界面类**（画面非常量、主题背景、明暗亮度、区域有内容、菜单/工具栏/状态栏文字像素、chrome 顺序、状态栏贴底、视口占比、面板方位、底部面板、模式/工作区/语言、状态栏片段、必须面板、英文无 CJK 等）；
- 判定：采集失败退 3、界面缺陷退 2、通过 0；报告写 `report.json` + `report.md` + 应用日志。

### 7.3 场景覆盖

- `tools/gui_acceptance.ps1`：**10 个场景**（4 布局 × 主题/语言组合、主题编辑器、窄窗口、restart_restore）；
- 五模式验收（`--expect-mode`）通过 CLI 手动执行过（`2d/3d/script/run/assets` 全部通过，证据 `.verify/runs/mode_*`、`docs/验收证据/10_模式_*.png`），**尚未并入脚本**；
- 未覆盖：真实鼠标事件、菜单展开截图、悬浮提示、拖拽指示器。

## 8. 架构地图

```text
┌───────────────────────── editor_app（Bevy 应用） ─────────────────────────┐
│ plugin.rs   资源装配/系统排序/启动恢复    actions.rs  UiAction 唯一执行器  │
│ preview.rs  2D/3D 预览相机与渲染目标      capture.rs  同帧截图+证据        │
│ config.rs   用户配置(v2)/退出写盘        scene_bridge.rs 场景→独立 World  │
└───────────────┬──────────────────────────────────────────────┬───────────┘
                │ UiAction 队列（单向）                          │ 只读状态
┌───────────────▼──────────────────────────────┐  ┌────────────▼───────────┐
│ editor_ui（无 Bevy 依赖，可 headless 测试）   │  │ editor_core            │
│ lib.rs 布局装配  docks 面板枚举  dev_modes    │  │ state 编辑器状态机      │
│ workspaces 布局集  workspace_bar  dev_mode_bar│  │ command/undo 可撤销命令 │
│ theme 语义主题  theme_editor  icons 字体      │  │ selection/project/i18n │
│ panels: hierarchy/inspector/assets/console/   │  └────────────┬───────────┘
│         history/viewport/viewport3d/script    │               │
└───────────────┬──────────────────────────────┘  ┌────────────▼───────────┐
                │ 直接读写（UI 私有状态）          │ scene_doc              │
                └──────────────────────────────────► document/property/     │
                                                    │ storage/path/registry  │
                                                    └────────────────────────┘
```

- **数据所有权**：场景文档、选择、撤销、日志在 `editor_core::编辑器状态`（`EditorStateHolder`）；
  布局/主题/语言/相机/脚本文档在 `editor_ui::界面状态`；Bevy 资源只做缓存（缩略图、图标纹理、配置）。
- **单向数据流**：面板只读文档，用户意图进 `动作队列`，由 `actions::执行动作队列` 在下一帧统一执行。
- **共享边界**：模式只交换"工作区集"，文档/选择/撤销/主题/语言不随模式重建。
- **持久化边界**：配置（`%APPDATA%\BevyStudio\config.ron`，版本 2 字段：`布局/v1`、`工作区/v3`、`主题`、`偏好`）与项目/场景文件完全分离；场景文件属于项目、进版本控制。
- **验收链路**：`gui_probe` 启动真实 exe → 应用内截图 + 证据 → probe 断言 → 报告。

### 8.1 易回归的耦合点

1. `egui_dock` 的 `fraction` 语义（第一个子节点比例）——历史上写反过两次；
2. 2D 渲染与 egui 叠加层共用"可见世界矩形"；3D 渲染与叠加层共用"三维相机参数"（本轮修复的正是后者符号）；
3. 模式 ↔ 工作区集 ↔ 存档 v3 三者的一致性（切换/保存/恢复/迁移）；
4. `UiAction` 与 `动作摘要` 的穷尽匹配（新增动作必须两处同时改）；
5. i18n 词表与扫描文件（`tools/gen_messages.py` 会因新增中文字面量而失败）；
6. 配置退出写盘与攒批写盘的交互；
7. `Tab` 枚举新增面板时所有布局预设、图标/工具栏与测试都要同步（脚本面板即如此）。

## 9. 技术债务（按风险分类）

### 9.1 高风险（影响正确性或可能导致数据丢失）

| 问题 | 现状 | 影响 |
| --- | --- | --- |
| 真实鼠标拖拽未自动化验收 | 只有 `move_tab`/`split` 数据路径测试 | Dock 交互回归无法被 CI 捕获；拖拽指示器/命中区域没有证据 |
| 模式切换缺少集成测试 | `切换模式` 有单元级覆盖（布局集交换），但没有"编辑→切模式→切回→数据一致"的集成测试 | 模式切换实际行为（尤其 3D 选中后切模式）未被钉死 |
| 配置写入的并发/半写风险 | 有临时文件+rename；退出写盘与攒批写盘共用 `写入配置文件` | 崩溃时机极端情况下仍可能丢最后一次布局（可接受但有记录） |
| 49 vs 48 图标不一致 | `circle-x.png` 未接入 | 轻微仓库冗余，不影响运行 |

### 9.2 主要缺口（影响核心工作流）

1. **3D 只有"观察+Inspector 数值编辑"**：没有视口内 gizmo、没有多选、拾取是屏幕最近点；
2. **运行模式不运行游戏**：只构建独立 World 与统计，没有游戏系统/渲染；
3. **菜单项无图标**；
4. **无原生多窗口**（仅主窗口 + 应用内浮窗）；
5. **代码编辑器无诊断/多标签/文件树**，块注释跨行不着色；
6. **资产无导入管线/元数据/依赖**，非图片无预览。

### 9.3 体验问题（专业性与易用性）

- 五模式 × 三主题 × 中英文的**完整组合**未一次性重跑（分项都过，但缺最终矩阵证据）；
- 菜单展开后的视觉、悬浮提示排版没有截图证据；
- 3D 中 Inspector 与视口的联动（选中→数值→视口）没有 GUI 证据；
- 资源模式布局约束（18% 下限）合理，但缺少"资源浏览器可用面积"的下限断言（已有 25%×55%）之外的宽/高独立下限；
- 导入/导出、另存为等对话框是原生阻塞对话框，自动化无法覆盖（设计上走后台线程，不影响主循环）。

### 9.4 可延后（高级能力）

LSP/补全、三维建模与网格编辑、PBR 材质/灯光、时间轴动画、粒子、UI 编辑器、在线资产库、
多窗口 DCC 式面板迁移、协作与版本控制集成。
